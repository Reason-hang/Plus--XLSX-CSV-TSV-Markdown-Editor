## 安装依赖

在仓库根目录执行：

~~~zsh
npm ci --no-audit --no-fund
npm --prefix themes/markdown-theme ci --no-audit --no-fund
~~~

如果需要固定 npm 缓存，可由本机自行增加 --cache 参数；缓存目录不属于仓库内容，也不应写入文档链接。

## 构建与打包

~~~zsh
npm run theme:build
npm run compile
npm run verify:security
npm run verify:local-patch
npm run verify:theme-system
npm run verify:docs
npm test
npx --yes @vscode/vsce@3.9.2 package --out "release/muhammad-ahmad.xlsx-viewer-1.9.98-local.16.vsix"
~~~

日常主题开发可用：

~~~zsh
npm run theme:watch
~~~

按 Ctrl + C 停止监听。构建失败时保留上一次成功 CSS 的行为由运行时加载器负责；主题构建器本身会以非零状态退出。

## 开发约束

- Less 只在 themes/markdown-theme 构建阶段编译，不在 Webview 运行时编译。
- 生成的 dist/markdown-theme.css 和 theme-manifest.json 由命令生成，不直接手改。
- 新增设置必须同时更新 package.json、运行时读取逻辑、验证脚本和文档。
- 所有 Webview `onDidReceiveMessage` 入口必须先通过 `src/shared/webviewMessageSchema.ts`；超限拒绝不得产生文件、网络或 `workspaceState` 副作用。
- Markdown 图片路径必须通过 realpath containment；工作区外图片只能来自 `xlsxViewer.md.externalResourceRoots` 明确配置的可信根目录。
- Markdown 主题选择器必须限定在预览或目录容器，不能覆盖 html、body 和工具栏。
- Markdown 工具栏不得再复用表格的固定头部测高和节点搬运逻辑。主工具栏与格式工具栏必须同属 `#markdownToolbarHost`，由 Flex 文档流自然占高；内容区只能使用剩余视口。切换编辑模式时自动聚焦必须使用 `preventScroll`。
- XLSX、CSV、TSV 代码不因 Markdown 主题需求顺手重构。

## 升级流程

1. 记录当前 Git 提交和 VSIX 文件，保留可回退基线。
2. 更新上游代码或依赖后先运行类型检查、Lint、主题构建和静态验证。
3. 公开发布前执行 `npm audit --audit-level=high --package-lock-only`，不得使用未经回归验证的 `npm audit fix --force`。
4. 检查 Markdown DOM、主题注入、配置变更和文件监听。
5. 打包新的本地 VSIX，并按测试清单做三 IDE 与 XLSX、CSV、TSV 人工回归。
6. 真实验收通过后再提交和推送；若失败，优先回退 VSIX 或 Git 提交，不修改用户 Markdown 正文。
