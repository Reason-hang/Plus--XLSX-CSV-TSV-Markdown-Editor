# Markdown 工具栏布局与返回顶部

适用版本：`2.0.1-local.3`。功能范围为 Markdown 主工具栏；表格和 Markdown 格式工具栏不参与此次自定义。

## 使用方法

1. 用本插件打开 Markdown 预览。搜索图标前的向上箭头是“返回顶部”。固定工具栏关闭且按钮已滚出视口时，可用命令面板中的 `Markdown: 返回文档顶部`。
2. 点击右侧齿轮，在设置面板顶部选择“自定义工具栏…”。
3. 已显示区拖动卡片排序；聚焦卡片后按 `Alt + 方向键` 移动。左右移动一项，上下移动一行，按当时的列数计算。
4. 卡片右侧 `×` 从工具栏隐藏该入口；未显示区点击 `+` 卡片，将其添加到已显示区末尾。说明图片／Logo 同样可以隐藏、显示和排序。
5. “预览布局”默认折叠，只展开一行顺序示意；实际按钮还会受当前阅读／编辑状态限制。
6. 所有操作先修改草稿。“应用布局”收到宿主成功响应后才确认保存；“恢复默认”也要应用后生效。存在草稿时首次关闭提示放弃，再次关闭或 Esc 才放弃。

布局保存在当前 IDE 用户配置 `xlsxViewer.md.toolbarLayout`，不写 Markdown，也不自动同步到另一 IDE。设置入口固定保留，保存／取消由编辑状态控制。隐藏入口不会禁用对应能力或重置其状态。

## 紧凑布局与交互

- 四列等宽卡片，6 px 间距，常规卡片最小高度 36 px。容器不足 620 px 时降三列、不足 460 px 时降两列；极窄容器不足 250 px 时单列保护，不缩小字号或截断名称。
- 面板上限 760 px，中间列表单独滚动，头部与底部操作保持可达。较长名称可换行，因此极窄视口卡片可以高于 36 px。
- 主工具栏保留横向滚动区，齿轮独立保留在右侧。此次不引入“更多”菜单，避免旧主题／设置组件的节点和样式依赖被菜单重挂载破坏。
- 弹窗有焦点循环、Esc 关闭和排序序号提示；存在保存请求时禁止修改草稿和关闭，15 秒未响应时提示重新打开核对。

## 架构与扩展约定

| 层 | 文件／职责 |
| --- | --- |
| 纯模型 | `src/shared/mdToolbarLayout.ts`：稳定 ID、动作／说明项、模式约束、默认顺序、校验与布局归一化；不依赖 DOM 或 VS Code |
| 呈现控制 | `src/webviews/md/mdToolbarController.ts`：移动原节点、计算最终显隐及可用状态、草稿面板、拖动与键盘交互 |
| 动作接入 | `src/webviews/md/mdWebview.ts`：既有动作处理、返回顶部、模式上下文；初始化按钮一次，布局更新不重建按钮或正文 |
| 宿主配置 | `src/mdEditorProvider.ts`：独立的 `saveMdToolbarLayout` 请求、同宿主串行保存、旧值摘要比较、结果回执和配置变更广播 |
| 信任边界 | `src/shared/webviewMessageSchema.ts`：Markdown 专用命令、布局数组／ID 长度与摘要校验 |

最终显示是“模式允许且用户未隐藏”；最终可用还要满足保存等运行状态。设置、保存、取消是显式受保护项目。启用／禁用 MD 用一个逻辑项目管理，按实际关联状态显示一个原按钮。

新增内置功能时：实现动作，在 `buildToolbarButtons()` 接入按钮，再在 `MD_TOOLBAR_ITEMS` 登记稳定 ID、节点 ID、文案和状态约束，补相应行为用例。普通动作无需改布局保存与排序算法。说明项登记为 `kind: decoration`，不能绕过清单另插一个不可管理节点。不要保存 HTML、脚本或任意命令到布局配置。

## 配置演进与冲突

```json
{
  "version": 1,
  "order": ["mdAssociation", "refresh", "backToTop", "search"],
  "hidden": ["rtl", "info"]
}
```

以上为片段示例，缺少的已知项目会按默认邻接关系补入。默认将返回顶部补在搜索前，但不覆盖用户已保存的顺序。未知 ID 保留在数据中、不会执行或渲染；重复项归一化，系统项目不能被隐藏。数组上限 64、ID 最长 64 字符。未知版本或损坏配置只回退显示默认布局，不自动写回；用户明确点击应用或恢复后应用才替换原配置。

没有有效自定义布局时兼容 `md.moveMdButtonsToEnd`；保存过新布局后旧位置开关不再干预。旧复选框从面板移除，配置声明保留弃用提示。

草稿期间收到外部配置更新时提示重新打开或恢复默认，不静默覆盖草稿。写入前比较基础摘要，同一个 Extension Host 内串行处理；这不是跨进程事务，不保证跨 IDE 同步或跨窗口原子合并。失败保留草稿并允许重试；超时可能已经写入，必须重新打开核对。

## 返回顶部状态约定

| 状态 | 行为 |
| --- | --- |
| 普通固定预览 | 预览滚动至顶部 |
| 普通非固定预览 | 主内容容器滚动至顶部 |
| 分屏，同步开启 | 源码编辑区和预览一起回顶 |
| 分屏，同步关闭 | 只回顶预览 |
| 所见即所得或历史只读 | 滚动预览，不保存、不修改模式 |

不改变横向位置，不主动更改选区，不重绘 Markdown。导航协调同步来源锁；命令面板只定位当前活动的 Markdown Webview，没有活动目标时提示用户，不选择任意第一篇文档。

- 补充浏览器边界验收通过：恢复默认后取消不落盘、外部布局变化保留脏草稿、历史只读隐藏编辑入口、所见即所得回顶不重建正文、非固定工具栏使用主内容容器回顶。
- 用户提出 IDE 限制前，VS Code Extension Host 的原 11 项与新增 8 项测试共 19 项通过。这不涵盖后来新增的真实 Webview 集成测试。

- 未经用户另行授权，不下载或升级 IDE，不启动额外 IDE 测试窗口，不重启或重载工作窗口。新测试入口必须显式指定已有可执行文件，否则直接退出；纯模型和浏览器测试不要求 IDE 更新。
- 安装版本、包哈希、远端 SHA 及最终运行验收分别记录在版本台账与包外交付清单中。CLI 安装不证明已开的窗口加载新版；需用户选择合适时机使插件加载后核验。

## 回退

保留 `.2` VSIX。回装旧扩展时布局配置可以保留，新版再安装后继续读取；旧版不使用新布局。回装不修复此前已损坏的文档，也不需要改动 Markdown 正文。此次配置为用户偏好，不进行破坏性数据迁移。
