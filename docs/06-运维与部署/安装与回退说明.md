# 安装与回退说明

适用于 XLSX、CSV、TSV、Markdown Editor 个人版。以下用 `2.1.0` 举例，覆盖 VS Code、Cursor 和 Antigravity IDE 的本地 VSIX 安装、加载核验和故障回退。不同 IDE 和配置文件分别执行、分别留证。

## 一页纸结构化总览

| 要完成什么 | 从哪里开始 | 完成的标志 |
| --- | --- | --- |
| 安装前准备 | 取得目标 VSIX、对应版本记录和 SHA-256。备份旧包、配置和涉及的用户文件 | 能确认包的版本、扩展 ID、构建来源及可回装版本 |
| 安装 | 在目标 IDE 的扩展面板选择安装 VSIX，也可用该 IDE 自带 CLI | 扩展详情或 CLI 列出 `muhammad-ahmad.xlsx-viewer@2.1.0` |
| 确认窗口加载 | 在同一 IDE 和 Profile 打开临时样本，明确选用本扩展的编辑器 | 能确认该窗口实际加载的版本、预览、编辑、保存和重开结果 |
| 异常时恢复 | 先保存草稿副本和磁盘版本，再决定修设置、重装或回装 | 可以用备份还原内容。旧版重新加载后，临时样本编辑和保存正常 |

个人版与上游商店版本沿用同一扩展 ID。对同一 IDE、同一安装位置侧载时，新包会替换原有的同 ID 版本。准备回退材料后，再在合适的时机安装。若需要同时比较两个版本，为它们指定不同的测试配置和扩展目录。

## 1. 安装前准备

### 1.1 取得安装包并核对身份

从维护者取得版本记录对应的 VSIX，或从明确的构建 SHA 自行打包。GitHub 候选分支提供源码和文档，安装需一个实际的 `.vsix` 文件。2.1.0 的构建与 IDE 证据分别记录在 [2.1.0 版本记录](../07-版本与发布/版本记录表-v2.2-续记.md#210)。

| 核对项 | 2.1.0 已交付包 |
| --- | --- |
| 文件名 | `xlsx-viewer-2.1.0.vsix` |
| 扩展 ID 与版本 | `muhammad-ahmad.xlsx-viewer@2.1.0` |
| 打包源码完整 SHA | `cd3309c71c8435b661c866a5c861ef09b17846d8` |
| 交付包 SHA-256 | `4d36661b65bd9783f5b2ffab38ad1a0806f7f65823273c3a5041a1b605c37954` |

下面命令可在任意终端目录执行。示例中的文件位于下载目录，包在别处时替换为你的绝对路径。出现哈希差异时，先查文件来源和是否拿错版本。自行打包时核对该次构建实际生成并交付的 SHA-256。

```bash
vsix_path="$HOME/Downloads/xlsx-viewer-2.1.0.vsix"
expected_sha256=4d36661b65bd9783f5b2ffab38ad1a0806f7f65823273c3a5041a1b605c37954
actual_sha256=$(shasum -a 256 "$vsix_path" | awk '{print $1}')
test "$actual_sha256" = "$expected_sha256" &&
  unzip -tq "$vsix_path"
```

如需查看包内版本和声明的 VS Code engine，可继续使用以下命令。库内的安装包声明可以核对基础兼容条件，各 IDE 的实际加载结果还要运行样本确认。

```bash
unzip -p "$vsix_path" extension/package.json |
  node -e 'const p=JSON.parse(require("node:fs").readFileSync(0,"utf8")); console.log(p.publisher+"."+p.name+"@"+p.version, p.engines.vscode)'
```

Windows 可在 PowerShell 用 `Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\实际目录\xlsx-viewer-2.1.0.vsix'` 计算同一文件的哈希。

### 1.2 备好需要恢复的内容

| 备份对象 | 需要记录的内容 |
| --- | --- |
| 旧版扩展 | 最后可用的旧 VSIX、扩展 ID、版本、SHA-256、适用的 IDE。使用 CLI 时先记录原安装版本 |
| IDE 配置 | 当前 IDE、Profile、用户设置与工作区设置中的 `xlsxViewer.*`、文件关联和快捷键。按自己的环境备份相关键及必要的 `settings.json`、`keybindings.json` |
| 主题与外部资源 | 自定义 CSS、主题 manifest、可信图片目录及路径。移动或回装后按路径逐一复核 |
| 用户文件与历史 | 可能被编辑的原始文件、未保存草稿副本、可用的历史快照。每个 IDE、Profile 的历史记录各自保存 |
| 工具栏与扩展状态 | 记录工具栏的顺序和隐藏项。当前布局优先读扩展全局状态里的 `mdToolbarLayout.v1`，没有新状态时读旧的 `xlsxViewer.md.toolbarLayout`。已有布局宜先截图或记录 |

在 macOS 默认配置中，可先查 `~/Library/Application Support/Code/User`、`~/Library/Application Support/Cursor/User`、`~/Library/Application Support/Antigravity IDE/User`。使用 Profile、远程宿主或自定义 `--user-data-dir` 时，按实际目录核对。历史快照位于扩展 `globalStorageUri` 下的 `.history`，文件标识与路径有关。需要回退时先复制备份，再在副本中恢复并对照。跨 IDE 恢复配置时逐项核对，公共状态库可能包含其他扩展和账号数据。[布局存储实现](../../src/shared/mdToolbarStorage.ts) · [历史路径实现](../../src/shared/versionHistory.ts)

## 2. 在目标 IDE 安装

### 2.1 用界面安装

1. 打开目标 IDE 的编辑器窗口，确认当前 Profile 和本地／远程宿主。Cursor 的 Agents Window 可先切到编辑器窗口，Antigravity 选用 **Antigravity IDE** 应用。
2. 按 macOS `⌘⇧P` 或 Windows／Linux `Ctrl+Shift+P`，运行 `Extensions: Install from VSIX...`。也可在扩展视图右上角菜单找到安装 VSIX。
3. 选择已核验的 VSIX，等安装成功，打开扩展详情核对 ID、版本和启用状态。若要安装到多个 IDE，在各目标窗口分别完成。
4. 若窗口提示加载新版，先保存正在处理的工作，再由操作者选择时机执行扩展宿主重启或 `Developer: Reload Window`。新开的隔离窗口也可用于验收。之后执行第 3 节的运行核验。

[VS Code 官方 VSIX 安装说明](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_install-from-a-vsix)

### 2.2 用命令行安装和确认版本

以下是 macOS 默认应用位置的参考。若 IDE 安装在其他目录，改用它实际的 CLI。使用非默认 Profile 或不确定 CLI 作用范围时，用对应窗口的界面安装。

| IDE | CLI 绝对路径 |
| --- | --- |
| VS Code | `/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code` |
| Cursor | `/Applications/Cursor.app/Contents/Resources/app/bin/cursor` |
| Antigravity IDE | `/Applications/Antigravity IDE.app/Contents/Resources/app/bin/antigravity-ide` |

任意终端目录可执行下方命令。先沿用第 1 节的 `vsix_path`，再将 `ide_cli` 指向本次的目标 IDE。两套 IDE 要分别执行并保存输出。

```bash
ide_cli='/Applications/Cursor.app/Contents/Resources/app/bin/cursor'
test -x "$ide_cli" &&
  test -f "$vsix_path" &&
  "$ide_cli" --install-extension "$vsix_path" --force &&
  "$ide_cli" --list-extensions --show-versions | grep -Fx 'muhammad-ahmad.xlsx-viewer@2.1.0'
```

上面 `--force` 用于明确以已审核的包替换同 ID 版本。预期查询到 `muhammad-ahmad.xlsx-viewer@2.1.0`。需要追溯安装证据时记录 IDE 版本、扩展 ID、安装位置和命令输出。仍运行的窗口是否已加载该包，继续按下一节核对。

## 3. 确认运行版本并做一次保存冒烟

在实际要用的 IDE 窗口，先在扩展详情确认 `2.1.0` 且为启用状态。用同一窗口打开下表的临时文件，选用本扩展以触发激活。当 IDE 提供 `Developer: Show Running Extensions` 时可检查宿主激活情况。完成操作后查磁盘，分别记录版本列表、宿主激活和窗口结果。

文件打开为普通文本时，从文件标签页使用 `Reopen Editor With...`，按格式选择本扩展。先用临时文件试开，再按需要决定是否设为该类型默认编辑器。

| 文件格式 | 编辑器显示名 | 最小检查 |
| --- | --- | --- |
| `.md` | `Markdown Viewer & Editor` | 打开预览，点击分屏编辑，在预览侧改正文，核对源码侧同步。手动保存后关闭文件标签，再从磁盘重开 |
| `.csv` | `CSV Viewer & Editor` | 用临时副本改一个单元格，保存、重开并核对目标值和其他列 |
| `.tsv` | `TSV Viewer & Editor` | 用含制表分隔符的临时样本编辑，核对重开后的列和保存后的分隔符 |
| `.xlsx` | `XLSX Viewer & Editor` | 用普通工作簿副本改一个单元格，保存后重开并核对。复杂图表、透视表及格式保真按专项用例验证 |

如果手头没有安全样本，在任意终端目录生成临时工作区和两个文本样本。打开输出路径对应的 `workspace` 目录进行验收，备份在它的上一级。

```bash
smoke_dir=$(mktemp -d "${TMPDIR:-/tmp}/xlsx-install-check.XXXXXX")
mkdir -p "$smoke_dir/workspace"
printf '%s\r\n' '# 安装验证' '' '临时正文 A。' '' '~~~text' '此行原样保留' '~~~' \
  > "$smoke_dir/workspace/check.md"
printf '%s\r\n' '名称,数量' '样例,12' > "$smoke_dir/workspace/check.csv"
cp "$smoke_dir/workspace/check.md" "$smoke_dir/check.before.md"
printf '%s\n' "$smoke_dir/workspace"
```

在 Markdown 分屏右侧将正文 `A` 改为 `B`，点击扩展的保存按钮后关闭标签页、重开。先目视确认正文为 `临时正文 B。`，再在同一终端对比字节。预期只改了正文中的一个字母，CRLF、代码围栏和其他内容一致。

```bash
node - "$smoke_dir" <<'NODE'
const assert = require('node:assert/strict');
const { readFileSync } = require('node:fs');
const { join } = require('node:path');
const dir = process.argv[2];
const before = readFileSync(join(dir, 'check.before.md'), 'utf8');
const expected = Buffer.from(before.replace('临时正文 A。', '临时正文 B。'), 'utf8');
const after = readFileSync(join(dir, 'workspace', 'check.md'));
assert.deepEqual(after, expected, '保存后的字节和预期不符');
console.log('通过：只修改了目标正文，其余内容和换行字节一致。');
NODE
```

如果确实要验收工具栏持久化，再打开齿轮 → 自定义工具栏，修改一项顺序或显隐并应用，关闭重开后检查。长文可另测浮动返回顶部。2.1.0 的自动保存默认采用上游设置，需自动保存时按格式在插件内开启，例如 `xlsxViewer.md.autoSave`、`xlsxViewer.csv.autoSave`，用临时文件核对实际写入时机。更完整的数据用例及真实 IDE 结果见 [测试与验收清单](../05-测试与验收/测试与验收清单.md) · [工具栏说明](../04-开发文档/Markdown工具栏布局与返回顶部.md) · [2.1.0 版本记录](../07-版本与发布/版本记录表-v2.2-续记.md#210)

## 4. 按需要恢复主题和设置

轻量配色与字号可从插件设置的“外观”调整。需要沿用外置 CSS 时，在目标 IDE 的当前 Profile 用户设置加入相关键，路径替换为本机绝对路径。

```jsonc
{
  "xlsxViewer.md.theme.enabled": true,
  "xlsxViewer.md.theme.cssFile": "/仓库绝对路径/themes/markdown-theme/dist/markdown-theme.css",
  "xlsxViewer.md.theme.manifestFile": "/仓库绝对路径/themes/markdown-theme/dist/theme-manifest.json",
  "xlsxViewer.md.theme.watch": true
}
```

启用后重开 Markdown 样本，核对主题状态、CSS 与 manifest 的实际文件。修改 Less 时，在源码仓库根目录执行 `npm ci --prefix themes/markdown-theme`，再执行 `npm run theme:build`。使用已随项目交付的主题时可直接引用已构建的文件。MPE 适配与构建细节见 [主题说明](../../themes/markdown-theme/README.md)。

## 5. 根据现象定位故障

| 现象 | 先检查哪里 | 解决与复验 |
| --- | --- | --- |
| VSIX 打不开或校验不通过 | 包名、SHA-256、ZIP 检查结果、包内版本 | 重新取得对应版本的包，校验通过后再侧载 |
| IDE 提示不兼容或找不到 CLI | 应用实际安装位置、IDE 版本、包内 `engines.vscode` | 选择有验证证据的 IDE／包组合。命令行路径有误时回到目标 IDE 的扩展界面安装 |
| 列表显示新版，窗口功能仍像旧版 | 当前 Profile、启用状态、加载的宿主、同 ID 的自动更新情况 | 保存工作后择时加载，在临时文件上复跑第 3 节。旧版本再次出现时检查该 IDE 的扩展更新设置 |
| 隔离窗口停在登录或欢迎页 | 当前窗口是否已进入编辑器，是否需要本人登录 | 由操作者完成官方登录或在已获授权的测试环境重试，记录窗口交互待验原因 |
| Markdown 打开成普通文本 | 标签使用的编辑器、工作区和默认关联 | 用 `Reopen Editor With...` 选择 `Markdown Viewer & Editor`，确认临时样本能预览 |
| 主题、外部图片或布局异常 | CSS／manifest、可信根路径与 `xlsxViewer.md.allowRemoteImages`，以及 Profile 内的工具栏状态 | 核对绝对路径与扩展状态，在允许的目录用副本复验。旧布局和当前新全局状态需分别核对 |
| 保存提示磁盘已被外部修改，或保存内容不符合预期 | 缓存草稿、磁盘文件、临时副本、最近历史快照 | 先另存草稿和磁盘副本，比较并保留两边差异。停止编辑原文件，按下一节恢复数据 |

## 6. 回退扩展与恢复数据

**优先保留现场。** 如果涉及错误覆盖或保存冲突，先把当前磁盘文件、可见草稿和可用历史复制到独立位置。对照备份选出要恢复的文件，再处理扩展版本。

1. **选旧包。** 从版本台账找到在同一 IDE 使用过的可用版本，核对旧 VSIX 的版本、扩展 ID 和 SHA-256。确认旧版本能读取你要保留的配置或数据。需要试兼容时先在隔离副本验证。
2. **回装。** 在同一目标 IDE 和 Profile 使用安装 VSIX，选择已核验的旧包。用 CLI 时沿用第 2 节的 `ide_cli`，按下面的方式传入旧包绝对路径。
3. **加载并复验。** 保存未完成工作后择时加载旧版，核对窗口用的版本。先在临时文件执行打开、编辑、保存、重开，确认问题消失。检查主题、快捷键、工具栏和工作区文件关联。
4. **按需恢复配置与正文。** 从备份找回具体设置和文件，先在副本中比对、预览，确认内容和路径后再替换。历史快照先核对时间和文件归属，然后将可恢复内容导出或另存。已写坏的文件由备份或可用历史恢复，安装旧版本负责替换扩展代码。
5. **留下回退记录。** 记录 IDE／Profile、旧包哈希、实际加载版本、数据或设置恢复范围、通过的测试与仍待处理事项。

CLI 回装在任意终端目录运行。把示例路径替换为你已校验的旧 VSIX。版本查询应返回此次回装的版本。

```bash
old_vsix_path="$HOME/Downloads/已核验的旧版安装包.vsix"
test -x "$ide_cli" &&
  test -f "$old_vsix_path" &&
  "$ide_cli" --install-extension "$old_vsix_path" --force &&
  "$ide_cli" --list-extensions --show-versions | grep -F 'muhammad-ahmad.xlsx-viewer@'
```

## 7. 从源码自行构建的入口

需要自行打包时，从版本台账的构建 SHA 创建隔离工作树，在其仓库根目录按维护手册的 P3、P4 运行 `npm ci`、生产构建、回归、VSIX 打包与哈希核对。日常安装只需要已核验的 VSIX。`npm test` 是扩展宿主研发测试入口，启动测试窗口须获授权，并用 `VSCODE_EXECUTABLE_PATH` 指向本机现有 IDE。完整的构建、发布和证据流程见 [上游升级与自研差异持续维护方案](上游升级与自研差异持续维护方案.md) · [当前项目状态与构建](../04-开发文档/当前项目状态与构建.md)。
