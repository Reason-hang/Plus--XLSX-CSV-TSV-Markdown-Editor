## 首次构建

在仓库根目录执行：

~~~zsh
npm ci --no-audit --no-fund
npm --prefix themes/markdown-theme ci --no-audit --no-fund
npm run theme:build
npm run package
npx --yes @vscode/vsce@3.9.2 package --out "release/muhammad-ahmad.xlsx-viewer-1.9.98-local.2.vsix"
~~~

VSIX 输出在 release/。该目录用于本地发布包，不作为主题源码目录。

## 安装 VSIX

在 VS Code、Cursor、Antigravity 中分别执行命令面板：

~~~text
Extensions: Install from VSIX...
~~~

选择生成的 VSIX 并重载窗口。当前包沿用上游扩展标识，因此会替换同标识的已安装版本。不要把解压目录直接复制到 IDE 扩展目录。

## 配置统一主题

在三个 IDE 的用户设置中配置同一个仓库内已编译 CSS 的绝对路径：

~~~jsonc
{
  "xlsxViewer.md.theme.enabled": true,
  "xlsxViewer.md.theme.cssFile": "/仓库绝对路径/themes/markdown-theme/dist/markdown-theme.css",
  "xlsxViewer.md.theme.manifestFile": "/仓库绝对路径/themes/markdown-theme/dist/theme-manifest.json",
  "xlsxViewer.md.theme.watch": true
}
~~~

MPE 的 Global style.less 只保留适配层导入，具体步骤见 [MPE 主题兼容与迁移](../03-设计研究/MPE主题兼容与迁移.md)。

## 日常维护

只修改 themes/markdown-theme/theme.less 或 partials/*.less，然后执行：

~~~zsh
npm run theme:build
~~~

开发期间可以执行 npm run theme:watch。修改后通过“显示外置 Markdown 主题状态”确认 CSS 状态和 SHA-256 信息。

上游升级后，先保留旧 VSIX 和 Git 提交，再执行完整自动化检查和人工验收。主题构建产物、manifest、迁移报告都应由命令重新生成。

## 回退与故障处理

| 现象 | 处理 |
| --- | --- |
| 不想继续使用补丁版 | 重新安装同 IDE 中的官方扩展 |
| 主题没有颜色 | 核对 enabled、CSS 绝对路径和 CSS 是否已构建 |
| 主题路径错误 | 执行主题状态命令，修正 cssFile |
| CSS 修改后无变化 | 确认 watch 开启，手动运行 npm run theme:build 并刷新预览 |
| 主题加载失败 | 查看主题输出通道；若有旧成功版本，运行时会继续使用旧主题 |
| 表格功能异常 | 先禁用外置主题复测，再判断是否属于上游回归 |

回退只替换扩展包或配置，不改写 Markdown 正文；mark 是标准 HTML 标签，文档内容仍可由其他 Markdown 预览器读取。
