# `v1.9.97` 与 `1.9.98-local.10` 功能差异清单

> 复核日期：2026-09-28。比较起点为原作者标签 `v1.9.97`／`cb1c765c0da95d49ecd50ec3b0e26ca7ca185ebb`，终点为个人 Fork 的 `1.9.98-local.10` VSIX 及其对应源码 `6d2d44dbe5c7308ba6d4edd170b43530f1ec4991`。这是一份**历史版本对比**，不是 Fork 当前 HEAD 或上游 `v2.0.1` 的功能表。

## 一、先看结论与证据边界

`1.9.98-local.10` 相对 `v1.9.97` 的主要增量集中在 **Markdown 外观与主题、重点高亮、图片路径兼容，以及保存与 Webview 输入安全治理**。XLSX／CSV／TSV 的统一网格、基本编辑、格式化、筛选、转换、版本历史等大功能在 `v1.9.97` 已存在；`.10` 对这些能力主要增加防护和边界处理，不能把它们算作 Fork 新增功能。

版本链是：上游 `v1.9.97` → Fork 自研 `.2/.3/.5/.6` → **合入上游 `v1.9.98`** → Fork `.7/.8/.9/.10`。因此 `.10` 并非只从 `.97` 单线自研而来。[上游标签页](https://github.com/Mahmadabid/XLSX-CSV-TSV-MARKDOWN-Editor-Vscode-Extension/tags)显示 `.97` 为 `cb1c765`、`.98` 为 `fd6ed72`；[Fork 的 `main`](https://github.com/Reason-hang/Plus--XLSX-CSV-TSV-Markdown-Editor)在本次浏览时指向后续文档提交 `c4bad3a`，**不能用该 HEAD 代替 `.10` 源码**。上游 `v2.0.1` 标签对应 `4d0c836`，不在本次差异范围内。

本地 `.10` VSIX 为 `release/muhammad-ahmad.xlsx-viewer-1.9.98-local.10.vsix`，SHA-256：`fd9ed64532dd6c9351b9671c69b55a4d2f9c7383630844efa2f526b93f31cf45`。包内 `package.json` 的版本为 `1.9.98-local.10`，与 `6d2d44d` 中的 `package.json` 字节一致；此提交之后至 `.10` 交付补记之间，`src/`、`resources/`、`themes/`、`package.json`、`package-lock.json` 无源码差异。扩展 ID 仍是 `muhammad-ahmad.xlsx-viewer`，同一 IDE 内会替换同 ID 版本。本次没有从运行中的 IDE 读取启用版本；“目前安装 `.10`”采用用户本轮陈述。下文的“存在”指源码和发布包证据，**不等于三 IDE 逐项真实验收**。

主要固定证据：[上游 `.97` 提交](https://github.com/Mahmadabid/XLSX-CSV-TSV-MARKDOWN-Editor-Vscode-Extension/commit/cb1c765c0da95d49ecd50ec3b0e26ca7ca185ebb)、[上游 `.98` 提交](https://github.com/Mahmadabid/XLSX-CSV-TSV-MARKDOWN-Editor-Vscode-Extension/commit/fd6ed727bf241f6fd2c1380a609e7c728e108ee4)、[Fork `.10` 代码提交](https://github.com/Reason-hang/Plus--XLSX-CSV-TSV-Markdown-Editor/commit/6d2d44dbe5c7308ba6d4edd170b43530f1ec4991)。本地使用 `git diff cb1c765..6d2d44d`、各功能提交和 VSIX 内容交叉核对。下表“修复”表示代码针对缺陷增加了处理，除特别说明外不表示本轮在真实 IDE 重现了修复前后行为。

## 五、`.10` 不具备或尚未验收的边界

1. **Preview Edit 保存并不保真。** `.10` 仍会将渲染后的预览 DOM 用 Turndown 反转换并全文写回；Mermaid、围栏代码及 Tab 排版可能失真。后来的[专项审计报告](../05-测试与验收/Markdown预览编辑数据保真与目录锚点审计报告-2026-09-20.md)已确认风险，但修复未进入 `.10`，也未进入当前 `.16` 源码。原子写入只保证完整地写入所收到的文本，不保证文本语义正确。测试保存必须使用临时副本。
2. **手写正文目录锚点的兼容问题仍在。** `.10` 的内部 `#fragment` 点击交给浏览器默认处理；片段与插件生成的标题 ID 不一致时可能跳到顶部。左侧自绘大纲的存在不代表正文目录链接都正确。
3. **`.11`–`.16` 是后续版本，不属于 `.10`。** `.11` 工具栏高度和深色表格交替行、`.12` 核心简体中文化、`.13/.14` 模式切换空白与滚动处理、`.15` 左侧大纲层级、`.16` 分栏输入跳动修复，均不能计入本次 `.97→.10` 增量。
4. **三 IDE 全量真实验收待补证。** 本轮核对 GitHub 标签、Git 提交、配置差异、VSIX 包内 manifest 与资源；没有执行 VS Code、Cursor、Antigravity 中逐项打开／编辑／保存测试。历史 Extension Host 在 macOS 曾 SIGABRT，不能把静态检查写成真实 IDE 验收。
5. **外置主题和 MPE 适配需要用户配置。** `.10` 包含工程与命令，但默认未启用主题，不会自动修改 MPE 的 `style.less`；因此“可配置能力存在”和“安装后立即看见统一主题”应分开理解。

**本质总结：** 以 `.97` 为对照，`.10` 的价值是给原有四格式编辑器增加可控的 Markdown 外观与主题，并系统收紧输入、资源和保存边界；它没有重做原作者的表格编辑器，也没有解决 Preview Edit 的无损保存模型。判断 Fork 功能归属时，应同时看引入提交、发布包与真实运行验证，避免把上游合入、源码存在和用户已验收混为一谈。
