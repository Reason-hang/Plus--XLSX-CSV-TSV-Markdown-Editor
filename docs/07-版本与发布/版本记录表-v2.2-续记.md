#### 4.2 逐项变更记录

**变更 FIX-01：预览编辑保存保真门禁与源码清洗范围**

- 类型：修复、修改。
- 故障／需求：预览编辑将 DOM 经 Turndown 整篇覆盖，扩展 Markdown 语义与代码围栏可能损坏；标题拷贝链接清洗也曾作用于保存结果。
- 原因／根因：渲染 DOM 不含原文全部语法信息；旧门禁只看围栏与 Tab，不能涵盖高亮、容器等。
- 实施内容与理由：记录进入预览编辑时的 HTML／往返基线；无改动时保存原始文本，有改动仅在基线可精确保真且不含已知扩展标签时允许，否则提示分栏编辑；保存不再运行标题链接清洗，预览清洗跳过围栏。
- 代码定位证据：修改前 `src/webviews/md/mdWebview.ts` · `performSave()`／`sanitizeMarkdownCopyLinkArtifacts()` · 父提交 `41994f1127b5ddaa1cafc901405aaa4d0feefa09` · L1349–L1393、L864–L877；修改后同文件 · `getPreviewEditHtml()`／`performSave()`／`sanitizeMarkdownCopyLinkArtifacts()` · 版本提交 `0c5e7cc3a6508e47672b43c54baf151a3993ee81` · L1191–L1214、L1391–L1445、L866–L889。辅助规则修改前 `src/webviews/md/previewEditSafety.ts` · `hasUnsafePreviewEditSource()` · 父提交同上 · L1–L4；修改后同文件 · `getPreviewEditTrailingNewlines()` · 版本提交同上 · L7–L15。
- 运行时调用链（源码）：预览保存 → 比较编辑前后 DOM 与原文往返 → 允许原文或转换结果／拒绝 → Provider 写文件。
- 验证证据：`npm run verify:security` 实际 PASS；`npm test` 11 项通过；复杂语法的真实 IDE 临时副本保存待验收。自动化不证明 Preview Edit 已能无损编辑所有 Markdown。
- 影响与兼容：部分富文本编辑保存会被明确拒绝；Split Edit 不受此门禁限制。未直接改用户原文件。
- 回退方式与限制：回装 `.1` VSIX 或检出父提交；回退会重新暴露原文失真风险，回装操作待验。

**变更 FIX-02：历史快照、恢复与主文件保存结果分离**

- 类型：修复、修改。
- 故障／需求：Markdown 版本恢复按钮的消息被校验器拒绝；历史快照失败可能阻断打开或使成功的保存显示失败。

**变更 FIX-03：CSV／TSV 与原子写的文件保真**

- 类型：修复、修改。
- 故障／需求：GBK 文件保存后中文不可逆损坏；UTF-8 BOM、CRLF、引用字段被重写；保存符号链接会把链接替换成普通文件。
- 原因／根因：旧转换器按 UTF-8 非严格解码并按统一格式整篇序列化；原子写对链接路径直接 `rename`。
- 实施内容与理由：严格 UTF-8 解码，记录 BOM／换行／原引用字段；无变动不写，格式无法往返时拒绝覆盖；原子写解析文件符号链接的真实目标，硬链接明确拒绝。
- 代码定位证据：修改前 `src/shared/fileConversionService.ts` · `parseDelimitedText()`／`serializeDelimitedRows()`／`createDelimitedConverter()` · 父提交 `41994f1127b5ddaa1cafc901405aaa4d0feefa09` · L85–L156、L223–L256；修改后同文件 · 相同函数与 `decodeDelimitedFile()` · 版本提交 `0c5e7cc3a6508e47672b43c54baf151a3993ee81` · L86–L194、L259–L305。修改前 `src/shared/atomicFile.ts` · `writeFileAtomically()` · 父提交同上 · L5–L39；修改后同文件 · 相同函数 · 版本提交同上 · L5–L57。
- 运行时调用链（源码）：表格保存 → 原文件严格解码与可往返检查 → 原子写；无法证明格式保真时拒绝主文件写入。
- 验证证据：本机 Extension Host 临时文件用例实际覆盖 GBK 拒绝且原字节不变、BOM／CRLF／引号保留、符号链接保留；11 项全部通过。
- 影响与兼容：非 UTF-8 或非规范 CSV／TSV 需用外部工具另存为 UTF-8 后编辑；ACL／扩展属性未保证保留，待补证。

#### 4.2 逐项变更记录

**变更 MD-SCROLL-01：固定分栏编辑的滚动容器**

- 类型：修复、修改。
- 故障／需求：用户反馈分栏编辑输入时整页上下跳动；关闭同步滚动后仍可复现。需要让编辑区与预览区承担各自的纵向滚动。
- 原因／根因：修复前非 Sticky 布局把 `#content` 设为可滚动容器，子面板允许内容溢出；它与预览全量重绘共同构成滚动竞争条件。此处是源码确认的风险条件，尚无四层滚动实时数据证明它是唯一根因。
- 实施内容与理由：非 Sticky 编辑状态让外层只分配视口高度，分栏两侧及目录各自滚动；只对编辑相关容器禁用滚动锚定，保留普通预览阅读行为。
- 代码定位证据：
  - 修改前／风险位置：`resources/md/mdWebview.css` · 非 Sticky `#content`、`.markdown-container` 与子面板规则 · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L216–L242。
  - 修改后位置：`resources/md/mdWebview.css` · `body:not(.sticky-toolbar-enabled).edit-mode`、分栏面板及 `overflow-anchor` 规则 · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L244–L282。
- 依赖链／资源链／运行时调用链：无；此项是布局规则调整。
- 验证证据：2026-09-28 在未改动 `.16` 功能源码的工作区执行 `npm run compile` 与 `npm run verify:local-patch`，均返回 0；后者检查相关 CSS 标记，不是浏览器布局断言。专项报告记录用户在真实 `.16` VSIX 中确认核心输入跳动消失；当时 IDE 名称、四层滚动数值及三 IDE 组合验收待补证。
- 影响与兼容：影响 Markdown 分栏编辑与 Sticky 开关下的滚动；不改保存格式、用户文件或设置键。极长文档与图片／Mermaid 组合的性能仍待验收。

**变更 MD-SCROLL-02：隔离预览重绘批次与同步测量**

- 类型：修复、修改。
- 故障／需求：输入后的全量预览替换会恢复滚动位置、刷新行映射，并触发图片与 Mermaid 异步处理；旧批次不应影响新批次，同步关闭时不应继续测量行映射。
- 原因／根因：修复前 `renderMarkdown()` 无批次标识，在 DOM 替换后立即测量，图片加载和 Mermaid 完成也没有旧批次守卫；同步函数没有重绘期间的回写阻断。这些是源码可见的竞争路径，分别造成跳动的贡献程度待运行时补证。
- 实施内容与理由：引入 `renderEpoch` 与渲染事务结束标记；旧帧和异步回调先核对批次；重绘期间跳过双向滚动回写；关闭同步或退出分栏时清空映射，减少无用测量。仍保留完整预览重绘。
- 代码定位证据：
  - 修改前／风险位置：`src/webviews/md/mdWebview.ts` · `renderMarkdown()` · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L890–L918；`refreshSyncMetrics()` 与双向同步函数 · 同一父提交 · L1369–L1373、L1402–L1405、L1428–L1431。
  - 修改后位置：`src/webviews/md/mdWebview.ts` · `finishRenderTransaction()`、`renderMarkdown()` · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L938–L994；`refreshSyncMetrics()` 与双向同步函数 · 同一版本提交 · L1446–L1457、L1486–L1489、L1513–L1516。

**变更 MD-DIAG-03：增加受约束的滚动诊断**
