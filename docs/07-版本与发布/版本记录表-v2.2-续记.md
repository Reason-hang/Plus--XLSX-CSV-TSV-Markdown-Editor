#### 4.2 逐项变更记录

**变更 MD-SCROLL-01：固定分栏编辑的滚动容器**

- 类型：修复、修改。
- 故障／需求：用户反馈分栏编辑输入时整页上下跳动；关闭同步滚动后仍可复现。需要让编辑区与预览区承担各自的纵向滚动。
- 原因／根因：修复前非 Sticky 布局把 `#content` 设为可滚动容器，子面板允许内容溢出；它与预览全量重绘共同构成滚动竞争条件。此处是源码确认的风险条件，尚无四层滚动实时数据证明它是唯一根因。
- 实施内容与理由：非 Sticky 编辑状态让外层只分配视口高度，分栏两侧及目录各自滚动；只对编辑相关容器禁用滚动锚定，保留普通预览阅读行为。
- 代码定位证据：
  - 修改前／风险位置：`resources/md/mdWebview.css` · 非 Sticky `#content`、`.markdown-container` 与子面板规则 · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L216–L242。
  - 修改后位置：`resources/md/mdWebview.css` · `body:not(.sticky-toolbar-enabled).edit-mode`、分栏面板及 `overflow-anchor` 规则 · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L244–L282。
- 依赖链／资源链／运行时调用链：无；此项是布局规则调整。
- 验证证据：2026-09-28 在未改动 `.16` 功能源码的工作区执行 `npm run compile` 与 `npm run verify:local-patch`，均返回 0；后者检查相关 CSS 标记，不是浏览器布局断言。专项报告记录用户在真实 `.16` VSIX 中确认核心输入跳动消失；当时 IDE 名称、四层滚动数值及三 IDE 组合验收待补证。
- 影响与兼容：影响 Markdown 分栏编辑与 Sticky 开关下的滚动；不改保存格式、用户文件或设置键。极长文档与图片／Mermaid 组合的性能仍待验收。
- 回退方式与限制：可回装本机 `.15` VSIX；其 SHA-256 为 `ccd606d0cbad2001a299391aa868539731d97c294cf96e3ad2ff31da058318e6`，本轮未实际回装。回退会恢复旧滚动行为，不会修复已受其他保存故障影响的用户文件。

**变更 MD-SCROLL-02：隔离预览重绘批次与同步测量**

- 类型：修复、修改。
- 故障／需求：输入后的全量预览替换会恢复滚动位置、刷新行映射，并触发图片与 Mermaid 异步处理；旧批次不应影响新批次，同步关闭时不应继续测量行映射。
- 原因／根因：修复前 `renderMarkdown()` 无批次标识，在 DOM 替换后立即测量，图片加载和 Mermaid 完成也没有旧批次守卫；同步函数没有重绘期间的回写阻断。这些是源码可见的竞争路径，分别造成跳动的贡献程度待运行时补证。
- 实施内容与理由：引入 `renderEpoch` 与渲染事务结束标记；旧帧和异步回调先核对批次；重绘期间跳过双向滚动回写；关闭同步或退出分栏时清空映射，减少无用测量。仍保留完整预览重绘。
- 代码定位证据：
  - 修改前／风险位置：`src/webviews/md/mdWebview.ts` · `renderMarkdown()` · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L890–L918；`refreshSyncMetrics()` 与双向同步函数 · 同一父提交 · L1369–L1373、L1402–L1405、L1428–L1431。
  - 修改后位置：`src/webviews/md/mdWebview.ts` · `finishRenderTransaction()`、`renderMarkdown()` · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L938–L994；`refreshSyncMetrics()` 与双向同步函数 · 同一版本提交 · L1446–L1457、L1486–L1489、L1513–L1516。
  - 异步边界：修复前 `requestLocalImageResolution()`、`renderMermaidFlowcharts()` · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L629–L631、L816–L839；修复后同名函数 · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L665–L668、L856–L883。
- 运行时调用链（源码证据）：`onEditorInput()` → 防抖预览更新 → `renderMarkdown()` → DOM 全量替换／滚动恢复 → 当前批次的图片、Mermaid 与映射更新；此链路是源码路径，非已取得的 IDE 事件跟踪。
- 验证证据：2026-09-28 `npm run compile`、`npm run verify:local-patch` 返回 0；静态脚本检查批次及滚动守卫存在。专项报告记录用户在真实 `.16` VSIX 中确认输入跳动消失；旧批次交错、同步开关组合及长文档性能的真实矩阵待补证。
- 影响与兼容：影响 Markdown 预览刷新、同步滚动及图片／Mermaid 渲染后的测量；不更改文件存储格式。全量重绘的性能成本仍存在。
- 回退方式与限制：可回装上述 `.15` VSIX，实际回装与行为回归未验证；回退会失去批次守卫，不是 Preview Edit 数据保真问题的解决办法。

**变更 MD-DIAG-03：增加受约束的滚动诊断**

- 类型：新增、修复。
- 故障／需求：需要区分编辑区、预览区、`#content` 和 Webview document 的滚动，避免仅凭视觉现象断言唯一根因；捕获监听还需避免把子容器事件误记为 document 滚动。
- 原因／根因：父提交只有双向同步滚动监听，没有四层容器诊断消息；未取得运行时滚动轨迹。
- 实施内容与理由：增加限次数、限时的滚动诊断及 Output Channel；诊断消息经共享 schema 校验；document 事件仅在目标确为 document、html 或 body 时记录。消息不包含 Markdown 正文和文件路径。
- 代码定位证据：
  - 修改前／缺口位置：`src/webviews/md/mdWebview.ts` · `wireEditor()` 原滚动监听 · 父提交 `1da57040ab0bf1bb9a0e766761887355a8ed80fc` · L3690–L3703；诊断函数、命令与 Output Channel 原先不存在。
  - 修改后位置：`src/webviews/md/mdWebview.ts` · `reportScrollDiagnostic()`、`wireEditor()` · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L104–L139、L3776–L3798；`src/shared/webviewMessageSchema.ts` · `validateWebviewMessage()` 的 `reportScrollDiagnostics` 分支 · 同一提交 · L367–L383；`src/mdEditorProvider.ts` · `MDEditorProvider` 消息分发 · 同一提交 · L518–L528。
- 运行时调用链（源码证据）：Webview 滚动／输入事件 → `reportScrollDiagnostic()` → `validateWebviewMessage()` → `MDEditorProvider` Output Channel；实际 IDE 输出内容待采集。
- 验证证据：`src/test/securityAndReliability.test.ts` · 诊断消息有效／无效输入断言 · 版本提交 `6d1c537fd4ab230b52c93f0fa611f087498a7c8f` · L65–L78；**断言存在不等于 Extension Host 已执行通过**。2026-09-28 `npm run verify:security` 返回 0，包含测试源编译与独立安全脚本；本轮未运行 Extension Host 测试，历史 macOS 启动曾以 `SIGABRT` 终止。
- 影响与兼容：增加本地诊断输出与受控 Webview 消息，不修改用户文件或设置。诊断输出的实际准确性仍需目标 IDE 采证。
- 回退方式与限制：回装 `.15` 可移除诊断；本轮未实测回装，回退后将失去四层滚动观察能力。
