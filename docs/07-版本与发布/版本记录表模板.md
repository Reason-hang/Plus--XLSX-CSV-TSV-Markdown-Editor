# 版本记录表（通用模板）

> 用途：供 AI 或维护者为任意软件项目填写可追溯的版本台账。
> 填写底线：版本、日期、状态、提交、构建产物和验证结论必须有源码、Git、CI/CD、构建日志或人工验收记录支撑；没有证据时写“待补证”，不得猜测。

## 1. 填写规则

1. 一个版本可以对应多个提交，禁止用单个 SHA 代替全部版本来源。
2. `versionName` 是面向用户的版本号；`versionCode` 或构建号用于排序、安装覆盖或发布平台识别。没有该机制时写“不适用”。
3. “生命周期”“质量门禁”“发布状态”必须分别填写，不能合并成一个“状态”。
4. 新增、修改、修复、删除四项必须全部出现；无对应事项时明确写“无”。
5. 兼容性和回滚结论必须说明数据、文件、数据库或配置的实际影响；未知时写“待补证”。

## 4. AI 填写前检查清单

1. 是否确认了 `versionName`、`versionCode/构建号`、发布日期、上一版本和 Git Tag？
2. 是否将功能代码、构建来源、交付、文档、回滚/恢复的 SHA 分开记录？
3. 是否把生命周期、质量门禁、发布状态拆成三条独立状态轴？
4. 是否完整填写新增、修改、修复、删除、受影响功能和数据与文件影响？
5. 是否明确了升级、覆盖安装、降级、迁移、回滚后数据保留及替代/恢复关系？
6. 是否把“自动化通过”与真实设备、真实 IDE 或正式发布状态分开表述？
