# 版本记录表模板

> 用途：交给 AI 或维护者填写项目版本台账。
> 规则：只填写已由源码、Git、构建产物或测试结果证实的事实；不确定时写“待补证”，不要猜测。

## 字段说明

| 字段 | 填写要求 |
| --- | --- |
| 版本 | 例如 `v1.2.0`，与实际发布版本一致 |
| 状态 | 当前、历史、上游基线或待补证 |
| 本次最重要变化 | 一句话说明用户最能感知的核心变化 |
| 新增 | 本版本首次提供的能力；没有写“无” |
| 修改 | 已有能力的行为、配置或交互调整；没有写“无” |
| 修复 | 已解决的故障、风险或兼容问题；没有写“无” |
| 删除 | 已移除的功能、依赖、入口或行为；没有写“无” |
| 受影响功能 | 明确到模块、页面、文件类型或用户场景 |
| 数据与文件影响 | 是否修改、迁移、兼容或影响用户数据/文件；没有写“无” |
| 提交 SHA | 实际承载该版本的 Git 提交；没有证据写“待补证” |
| 验证与交付 | 区分自动化验证、人工验收、安装包/发布状态 |

## 版本总览

| 版本 | 状态 | 本次最重要变化 | 新增 | 修改 | 修复 | 删除 | 受影响功能 | 数据与文件影响 | 提交 SHA | 验证与交付 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `vX.Y.Z` | 当前/历史/待补证 | [一句用户价值] | [新增能力/无] | [修改内容/无] | [修复内容/无] | [删除内容/无] | [模块或场景] | [影响说明/无] | `[完整 SHA]` | [自动化、人工、安装包状态] |

## 版本详情

### vX.Y.Z

- 本次最重要变化：[一句用户价值]
- 新增：[能力；没有则写“无”]
- 修改：[调整；没有则写“无”]
- 修复：[故障或风险；没有则写“无”]
- 删除：[功能、依赖、入口或行为；没有则写“无”]
- 受影响功能：[模块、页面、文件类型或用户场景]
- 数据与文件影响：[是否需要迁移、是否兼容旧数据、是否会改写文件；没有则写“无”]
- 提交 SHA：`[完整 SHA 或待补证]`
- 验证与交付：[自动化验证；人工验收；安装包、发布链接或待发布状态]

## 填写检查清单

1. 版本号是否与实际发布版本一致？
2. “本次最重要变化”是否是用户可理解的结果，而不是代码文件名？
3. 新增、修改、修复、删除是否都已填写；没有的是否明确写“无”？
4. 数据与文件影响是否说明了兼容、迁移、覆盖或无影响？
5. SHA、验证和安装包是否有证据；没有是否标为“待补证”？
