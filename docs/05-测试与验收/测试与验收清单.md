## 验收原则

工具栏检查草稿取消、拖动／Alt 排序、Logo 显隐、失败重试、模式切换后的隐藏保持和历史只读；上游浮动回顶与自动保存分别验证。`.3` 的 Cursor 宿主配置未注册测试失败是历史事实，候选版使用扩展状态存储，浏览器替身的保存结果不能替代真实宿主落盘和重开验证。功能归属与待验项见 [自研差异台账](../07-版本与发布/自研差异台账.md)。

本机限制：不自动下载／升级 IDE、不新启测试窗口、不重启／重载工作窗口。`npm test` 和 `out/test/runTest.js` 仅在获授权且指定已有 `VSCODE_EXECUTABLE_PATH` 后执行；默认缺路径即失败退出。纯模型测试和浏览器夹具不依赖启动 IDE。

自动化构建只能证明代码、配置和产物满足静态约束，不能代替真实 VS Code、Cursor、Antigravity 的安装和交互验证。主题系统与表格功能分别验收，避免“主题通过”被误认为“所有编辑器功能通过”。

## 自动化检查

在仓库根目录执行：

| 命令 | 验证内容 | 通过标准 |
| --- | --- | --- |
| npm run theme:build | Less 编译、CSS 作用域、manifest | 返回 0，生成 CSS 和 manifest |
| npm run theme:audit | MPE 样式迁移扫描 | 生成报告和迁移草稿 |
| npm run check-types | TypeScript 类型 | 返回 0 |
| npm run lint | ESLint | 不能有 error；warning 必须注明来源 |
| npm run test:local | 模型、Provider、主题、表格及保存边界的隔离测试 | 返回 0；不代表真实 IDE 验收 |
| npm test | 授权后的 Extension Host 回归 | 显式指定已有 IDE，测试全部通过；缺少路径时退出，不自动下载 |
| npm run package | 生产构建 | 返回 0，生成 dist/ 产物 |
| @vscode/vsce package | VSIX 组装 | 包内无主题工程 node_modules |
| npm audit --audit-level=high --package-lock-only | npm 锁文件漏洞 | 记录实际运行日期、结果及无法核验的项目 |

本轮生产构建无 lint error，保留 5 条原有 curly warning。本轮本地测试通过 18 项及 4 组隔离脚本；尚未运行真实 IDE 的 Extension Host 测试或在线依赖审计。历史 `.10` 审计见 [历史报告](./代码审计报告-2026-09-15-v1.9.98-local.10.md)，不能替代当前验证。

人工验收步骤：

1. 安装 VSIX；仅在用户明确授权后，让运行中的窗口加载新版本。安装记录与实际加载结果分别记录。
2. 配置 xlsxViewer.md.theme.enabled、cssFile、manifestFile 和 watch。
3. 打开 Markdown，确认编辑、预览、目录、保存和 mark 高亮。
4. 修改 theme.less，运行 npm run theme:build，确认 CSS 文件变化并刷新预览。
5. 临时制造 CSS 语法或路径错误，确认预览不白屏且状态可定位。
6. 分别打开并保存 XLSX、CSV、TSV，确认原功能无回归。
7. 将快捷键冲突、字号配置和窗口重载结果记录到对应版本记录表，不能只写“已验证”。
8. 在 `Settings` 面板分别修改高亮、标题颜色、预览和编辑字号/行高，确认当前 Webview 立即更新；重载窗口后再次打开面板，确认值仍保持且空的预览字段继续跟随 IDE 主题。
9. 缩窄 `Split Edit` 与 `Preview Edit`，确认格式工具栏自动换行、所有工具组可见且可点击，内容区不覆盖格式栏；检查深色表格奇数行为 `#161617`、偶数行为 `#27272A`。
10. 断开网络后打开包含公式的 Markdown，确认 KaTeX 仍能渲染；对工作区外图片只配置明确可信根，确认未授权 symlink 不显示。
11. 记录超限消息、超大编辑批次、非法坐标、超大合并和 StyleStorage 超限的拒绝结果，确认原文件和上一份有效元数据未被破坏。
12. 打开长 Markdown 并进入 `Split Edit`；分别关闭/开启“同步滚动”、关闭/开启“粘性工具栏”，连续输入、删除、粘贴和中文输入法上屏。确认编辑区、预览区和 Webview 外层没有非用户触发的上下跳动。
13. 在同一次复现后打开输出面板的 `XLSX Viewer Markdown Scroll Diagnostics`，确认日志包含 `editor-input`、`render-before-replace`、`render-after-replace`、`render-transaction-complete`，以及四类 `scrollTop`、`syncScroll`、`stickyToolbar`；只把实际变化的容器认定为根因证据。

安全专项至少补测：Markdown 中的事件属性、脚本、`<style>`、不安全链接和 Mermaid 代码；表格单元格中的 HTML、属性引号、`0`、`false`、富文本；在外部程序修改文件后再保存，确认扩展拒绝静默覆盖；模拟转换后样式应用失败，确认目标文件仍被正确报告为已转换。

## 失败处理

- 配置错误：先执行“显示外置 Markdown 主题状态”，核对绝对路径。
- manifest 不匹配：重新运行 npm run theme:build，不要手改 manifest。
- 主题选择器无效：检查目标 Webview 的 DOM class，再更新主题 partial。
- 主题编译失败：修复 Less，运行时会继续使用上一次成功 CSS；不要删除旧产物。
- 表格功能异常：关闭外置主题后复测，区分主题问题和上游功能问题。

## 上线门槛

本地侧载交付至少满足：

- 自动化检查全部通过。
- VSIX 可以安装并能回退。
- 至少一套真实 IDE 完成 Markdown 主流程。
- XLSX、CSV、TSV 各完成一次打开、编辑、保存回归。
- 主题路径、构建失败、运行时回退和升级步骤有记录。

Marketplace 或 Open VSX 发布还需要额外完成 Publisher、扩展身份、许可证、隐私声明、商店元数据和多平台发布审核，本清单不把它们默认为已完成。
