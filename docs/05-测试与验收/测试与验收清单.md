## 验收原则

自动化构建只能证明代码、配置和产物满足静态约束，不能代替真实 VS Code、Cursor、Antigravity 的安装和交互验证。主题系统与表格功能分别验收，避免“主题通过”被误认为“所有编辑器功能通过”。

## 自动化检查

在仓库根目录执行：

| 命令 | 验证内容 | 通过标准 |
| --- | --- | --- |
| npm run theme:build | Less 编译、CSS 作用域、manifest | 返回 0，生成 CSS 和 manifest |
| npm run theme:audit | MPE 样式迁移扫描 | 生成报告和迁移草稿 |
| npm run check-types | TypeScript 类型 | 返回 0 |
| npm run lint | ESLint | 不能有 error；warning 必须注明来源 |
| npm run verify:local-patch | mark 标签、固定设置和运行时标记 | 返回 0 |
| npm run verify:theme-system | 外置主题配置、命令、产物和注入逻辑 | 返回 0 |
| npm run verify:docs | 文档索引、内部链接和跨平台路径 | 返回 0 |
| npm run package | 生产构建 | 返回 0，生成 dist/ 产物 |
| @vscode/vsce package | VSIX 组装 | 包内无主题工程 node_modules |

当前已知的 5 个 ESLint warning 来自未修改的上游文件：src/shared/versionHistory.ts 3 个 curly，src/spreadsheet/spreadsheetUtilities.ts 2 个 curly。它们不是本次主题增强引入的 error。

人工验收步骤：

1. 安装 VSIX 并重载窗口。
2. 配置 xlsxViewer.md.theme.enabled、cssFile、manifestFile 和 watch。
3. 打开 Markdown，确认编辑、预览、目录、保存和 mark 高亮。
4. 修改 theme.less，运行 npm run theme:build，确认 CSS 文件变化并刷新预览。
5. 临时制造 CSS 语法或路径错误，确认预览不白屏且状态可定位。
6. 分别打开并保存 XLSX、CSV、TSV，确认原功能无回归。

## 失败处理

- 配置错误：先执行“显示外置 Markdown 主题状态”，核对绝对路径。
- manifest 不匹配：重新运行 npm run theme:build，不要手改 manifest。
- 主题选择器无效：检查目标 Webview 的 DOM class，再更新主题 partial。
- 主题编译失败：修复 Less，运行时会继续使用上一次成功 CSS；不要删除旧产物。
- 表格功能异常：关闭外置主题后复测，区分主题问题和上游功能问题。

## 上线门槛

本地侧载交付至少满足：

- 自动化检查全部通过。
- VSIX 可以安装并能回退。
- 至少一套真实 IDE 完成 Markdown 主流程。
- XLSX、CSV、TSV 各完成一次打开、编辑、保存回归。
- 主题路径、构建失败、运行时回退和升级步骤有记录。

Marketplace 或 Open VSX 发布还需要额外完成 Publisher、扩展身份、许可证、隐私声明、商店元数据和多平台发布审核，本清单不把它们默认为已完成。
