### DEP-001：已知依赖告警导致开发/构建链存在高危组件

- 问题编号：DEP-001
- 问题标题：`serialize-javascript` high、`diff` low、Mocha 传递依赖及 ExcelJS 使用的 `uuid` moderate
- 风险等级：P1（初始 `.7`）；`.8` 已修复
- 问题类型：第三方依赖/供应链
- 置信度：高
- 影响模块：开发测试链、ExcelJS 运行时依赖解析、VSIX 构建环境
- 故障根因：`.7` 锁文件解析为 `diff@7.0.0`、`serialize-javascript@6.0.2`、`uuid@8.3.2`；npm advisory 分别报告 DoS、RCE 和 UUID buffer 边界问题。npm 建议的自动修复会把 Mocha 或 ExcelJS 降到不合适的主版本。
- 代码证据：`.7` 的 `npm audit --package-lock-only` 返回 `low:2, moderate:3, high:1`；`package.json` 直接依赖 `@vscode/test-cli`、`mocha`、`exceljs`。
- 文件路径：`package.json`、`package-lock.json`
- 代码行号：`package.json` overrides 区域；锁文件对应 `node_modules/diff`、`serialize-javascript`、`uuid`
- 调用链：`vscode-test → @vscode/test-cli → mocha → diff/serialize-javascript`；`exceljs → uuid`
- 触发条件：安装 `.7` 开发依赖并运行在线 npm advisory 审计。
- 复现步骤：在含原始 `.7` 锁文件的干净目录运行 `npm audit --json --package-lock-only`。
- 复现结果：6 项告警，包含 1 high。
- 实际表现：构建仍可能成功，但开发/测试工具链包含已知漏洞，公开维护和 CI 环境不满足依赖门禁。
- 预期表现：锁文件无可接受范围内的已知 high/moderate/low 告警，且不牺牲 ExcelJS 兼容性。
- 影响范围：主要是开发/构建链；`uuid` 还会被 ExcelJS 运行时调用。
- 安全影响：高危序列化依赖可能在受影响的工具调用场景中触发 RCE/DoS；本地 VSIX 不把 devDependencies 打包进去，但源码仓库和 CI 仍受影响。
- 业务影响：依赖安装、CI 审计和公开发布被阻断。
- 数据影响：无直接用户文件数据影响。
- 性能影响：无可证明的正常路径性能影响。
- 利用难度：需要构造依赖工具输入或影响构建/测试环境，非普通 Markdown 打开路径。
- 是否可远程利用：不能通过 VSIX 正常 Webview 直接远程利用；若 CI 接收不可信测试输入，则存在间接攻击面。
- 是否需要登录权限：不需要应用登录；需要开发/CI 环境执行受影响依赖。
- 修复建议：使用兼容版本的根级 overrides，锁定 `diff:^8.0.4`、`serialize-javascript:^7.0.6`，并为 ExcelJS 的 `uuid` 覆盖 `^11.1.1`；避免 `npm audit fix --force`。
- 短期止血方案：不在不可信数据上运行测试工具；公开发布前阻断高危依赖。
- 长期治理方案：每次版本发布执行 `npm ci`、`npm audit --package-lock-only`、`npm audit --omit=dev`，并建立依赖升级窗口和变更记录。
- 验证方式：在临时干净目录复制当前 package 文件，运行 `npm ci --ignore-scripts`、两种 `npm audit`。
- 回归测试要求：类型检查、生产构建、安全回归、4 项 Extension Host 测试、VSIX 验包。
- 修复优先级：已完成，P1 关闭。
- 修复依赖：网络可用、npm registry 可访问；不依赖强制升级。
- 当前残余风险：依赖 advisory 会随数据库变化，需要每次发布重新审计。

### SEC-001：Markdown CSP 中不必要的 `unsafe-eval`（已修复）

- 问题编号：SEC-001
- 问题标题：Markdown Webview CSP 放宽了不需要的脚本执行能力
- 风险等级：P2（初始）；`.8` 已修复
- 问题类型：Webview 内容安全策略
- 置信度：高
- 影响模块：Markdown Webview
- 故障根因：CSP `script-src` 曾包含 `'unsafe-eval'`，但源码未发现 `eval()` 或 `new Function()` 的实际调用。
- 代码证据：初始 `.7` `src/mdEditorProvider.ts` CSP；`rg` 未发现实际动态代码执行。
- 文件路径：`src/mdEditorProvider.ts`、`scripts/verify-security.mjs`
- 代码行号：修复后 `src/mdEditorProvider.ts:991`；回归断言位于 `scripts/verify-security.mjs`
- 调用链：`MDEditorProvider.getWebviewContent → CSP meta → mdWebview.js`
- 触发条件：任意 Markdown 预览 Webview 创建。
- 复现步骤：读取 Webview HTML 并检查 `script-src`。
- 复现结果：`.7` 包含 `unsafe-eval`；`.8` 只保留 nonce。
- 实际表现：脚本策略比实际需求宽松。
- 预期表现：脚本仅允许扩展资源和随机 nonce。
- 影响范围：Markdown Webview 的脚本策略。
- 安全影响：若未来出现 DOM 注入或第三方脚本路径问题，攻击者可利用更宽松的 eval 能力扩大影响。
- 业务影响：无正常功能损失。
- 数据影响：无。
- 性能影响：无。
- 利用难度：需要先取得 Webview 脚本注入能力。
- 是否可远程利用：不能单独远程利用。
- 是否需要登录权限：否。
- 修复建议：删除 `unsafe-eval`，保留 nonce；新增回归断言防止回退。
- 短期止血方案：升级至 `.8`，关闭旧 VSIX。
- 长期治理方案：任何新增第三方脚本都必须通过 CSP 与源码审查。
- 验证方式：安全脚本和 Extension Host Webview CSP 测试均检查无 `unsafe-eval`。
- 回归测试要求：Markdown/表格 Webview 都必须使用 nonce，不能出现 `script-src unsafe-inline/eval`。
- 修复优先级：已完成，P2 关闭。
- 修复依赖：无。
- 当前残余风险：Markdown CSP 仍允许 `style-src 'unsafe-inline'`，这是现有动态样式逻辑所需，需单独评估 nonce 化。

### SEC-002：KaTeX CSS 通过外部 CDN 加载

- 问题编号：SEC-002
- 问题标题：数学公式样式依赖 `cdnjs.cloudflare.com`
- 风险等级：P2
- 问题类型：第三方资源/供应链/离线可用性
- 置信度：高
- 影响模块：Markdown 公式预览
- 故障根因：`getWebviewContent` 生成固定外部 `<link>`，而运行时已经包含 `katex` 包。
- 代码证据：`<link href="https://cdnjs.cloudflare.com/ajax/libs/KaTeX/0.16.47/katex.min.css">`；CSP `style-src` 与 `font-src` 允许 https。
- 文件路径：`src/mdEditorProvider.ts`
- 代码行号：`997`
- 调用链：Markdown Webview → 外部 CSS → 外部 KaTeX 字体资源
- 触发条件：预览包含数学公式且网络/CDN 可用。
- 复现步骤：断开网络或阻断 cdnjs 后打开含 `$x^2$` 的 Markdown。
- 复现结果：公式 HTML 仍生成，但样式/字体可能降级或显示异常。
- 实际表现：存在运行时网络依赖和外部供应链依赖。
- 预期表现：公式 CSS 与字体随 VSIX 一起交付，离线也能渲染。
- 影响范围：公式视觉样式、启动时网络请求。
- 安全影响：受信任 CDN 内容变化可影响 Webview 样式和字体；当前 `script-src` 不允许该 CDN 执行脚本，因此不是已确认脚本执行链。
- 业务影响：离线环境公式显示不完整。
- 数据影响：CSS 本身不应读取 Markdown 内容，但外部请求会暴露访问时机和网络元数据。
- 性能影响：首次加载增加网络等待。
- 利用难度：依赖 CDN 被篡改或用户网络被劫持。
- 是否可远程利用：需要外部资源供应链或网络攻击面，非本地文件直接利用。
- 是否需要登录权限：否。
- 修复建议：把 `katex.min.css` 和所需字体复制到 `resources/md/katex`，通过 `asWebviewUri` 加载，收紧 style/font CSP 到 `${cspSource}`。
- 短期止血方案：保持固定版本 URL，继续禁止外部脚本；可信网络下使用 `.8`。
- 长期治理方案：本地化 CSS/字体并在构建中记录 KaTeX 版本与文件 hash。
- 验证方式：离线 Webview/公式快照、VSIX 包内容和 CSP 断言。
- 回归测试要求：公式 HTML、视觉样式、字体、PDF 导出均需回归。
- 修复优先级：P2，下一安全治理版本。
- 修复依赖：需增加资源文件和 VSIX 体积，需重新验包。
- 当前残余风险：`.8` 未修复，已明确记录为待治理项。

### SEC-003：Markdown 图片、PDF、反馈消息缺少统一 payload 上限

- 问题编号：SEC-003
- 问题标题：Webview 消息可提交超大数组、Base64 或反馈正文
- 风险等级：P2
- 问题类型：输入边界/本地 DoS/数据外传边界
- 置信度：中高
- 影响模块：Markdown Webview 消息处理
- 故障根因：`resolveImageUris` 遍历任意长度 `sources`；`savePdfData` 对任意长度 Base64 调用 `Buffer.from`；`submitFeedback` 对任意对象序列化并发送到固定 Google Forms。
- 代码证据：`Array.isArray(message.sources)` 后直接两次遍历；`Buffer.from(base64Data, 'base64')` 前只有非空校验；反馈请求没有 body 大小限制。
- 文件路径：`src/mdEditorProvider.ts`
- 代码行号：`445-492`、`722-746`、`836-858`
- 调用链：Markdown Webview → `onDidReceiveMessage` → 文件/网络操作
- 触发条件：恶意 Markdown 或被篡改的 Webview 向 Extension Host 发送大 payload。
- 复现步骤：构造数十万图片源、超大 Base64 或超长反馈字段并发送对应 command。
- 复现结果：可能出现 CPU、内存、临时文件或网络请求体放大。
- 实际表现：没有统一、可审计的字节/条数上限。
- 预期表现：超过上限立即拒绝并向 Webview 返回可理解错误。
- 影响范围：本地 IDE 进程和用户选择的输出文件；反馈功能还有第三方网络边界。
- 安全影响：本地 DoS；反馈内容可能被发送到固定第三方表单。
- 业务影响：预览卡顿、导出失败或反馈提交异常。
- 数据影响：正常用户主动提交的反馈数据会离开本机；恶意 Webview 可扩大提交内容。
- 性能影响：高，尤其是图片资源根和 Base64 解码。
- 利用难度：中，需要控制 Markdown/ Webview 内容。
- 是否可远程利用：通常需要本地打开恶意文件；不是网络服务远程利用。
- 是否需要登录权限：否。
- 修复建议：设置 sources 条数、单项长度、Base64 解码后最大字节、反馈 body 最大字节，并统一做对象字段白名单。
- 短期止血方案：只打开可信 Markdown，暂不使用反馈/超大 PDF 导出。
- 长期治理方案：抽取 Webview message schema 校验器，所有 command 先通过类型、大小和枚举校验。
- 验证方式：加入超长输入拒绝的单元测试和 Extension Host 测试。
- 回归测试要求：正常图片解析、PDF 导出、反馈提交仍成功；超限返回失败且不写文件/发请求。
- 修复优先级：P2。
- 修复依赖：需要定义用户可接受的 PDF/图片批量上限。
- 当前残余风险：`.8` 未改行为，保留为下一安全治理版本事项。

### SEC-004：表格保存消息的批量编辑和坐标边界较宽

- 问题标题：`saveXlsxEdits`/分隔文件保存接受未限长的 edits、operations、styles
- 风险等级：P2
- 问题类型：输入校验/资源放大
- 置信度：高
- 影响模块：XLSX、CSV、TSV 保存 Webview
- 故障根因：数组只检查 `Array.isArray`，坐标只检查 `typeof number` 或真值，未统一验证有限整数、最大行列和单次 batch 大小。
- 代码证据：`saveXlsxEdits` 读取四个数组后直接遍历；ExcelJS 对大坐标可能创建稀疏结构；分隔文件路径会扩展 rows/columns。
- 文件路径：`src/spreadsheetEditorProvider.ts`
- 代码行号：`1868-1900` 及 `saveDelimitedFileAndStyles` 相关实现
- 调用链：表格 Webview → `saveXlsxEdits` → ExcelJS/CSV 写入 → 原子替换
- 触发条件：恶意或异常 Webview 消息包含大量 edits、超大 row/col 或大量合并操作。
- 复现步骤：发送带百万级坐标或超长 operations 的保存消息。
- 复现结果：可能触发稀疏工作表扩张、长时间写入或内存峰值。
- 实际表现：正常消息能保存，但异常输入的拒绝边界不统一。
- 预期表现：输入超限时不读取/写回文件，并返回明确错误。
- 影响范围：表格文件保存与 IDE 进程资源。
- 安全影响：本地恶意文件造成资源消耗；被攻陷 Webview 可放大写入。
- 业务影响：卡顿、保存超时或用户误以为保存成功。
- 数据影响：若异常操作部分完成后失败，可能增加恢复复杂度；当前保存前仍有指纹保护。
- 性能影响：高，ExcelJS 稀疏结构和大批量操作可能显著放大。
- 利用难度：中。
- 是否可远程利用：否，通常需要本地打开恶意文件。
- 是否需要登录权限：否。
- 修复建议：统一限制 batch 条数、文本长度、dropdown 数量、row/col 最大值和 merge 面积；拒绝而不是静默截断。
- 短期止血方案：避免打开来源不明的超大表格，保留现有 1M cell 读取上限。
- 长期治理方案：抽取表格消息 schema/coordinate validator，所有保存操作共享边界常量。
- 验证方式：构造超限消息，确认没有写文件；正常编辑、控件、合并和样式回归通过。
- 回归测试要求：CSV/TSV/XLSX 各覆盖正常和超限输入。
- 修复优先级：P2。
- 修复依赖：需要和现有大文件上限、用户真实表格样本一起确定阈值。
- 当前残余风险：`.8` 未改行为，列为后续深度审计与修复项。

### SEC-005：路径检查未解析符号链接

- 问题编号：SEC-005
- 问题标题：`isPathWithin` 仅按 lexical path 判断目录包含关系
- 风险等级：P2
- 问题类型：本地文件边界/符号链接
- 置信度：中
- 影响模块：Markdown 相对文件打开、图片和主题文件边界
- 故障根因：`path.relative(path.resolve(root), path.resolve(candidate))` 不解析 realpath；工作区内 symlink 可指向工作区外。
- 代码证据：`src/shared/pathSafety.ts` 明确注明只防普通 `..` 穿越；调用方允许可信用户使用工作区 symlink。
- 文件路径：`src/shared/pathSafety.ts`、`src/mdEditorProvider.ts`
- 代码行号：`pathSafety.ts:8-19`；`mdEditorProvider.ts:749-821` 等
- 调用链：Markdown 链接/图片 → 路径规范化 → `isPathWithin` → 打开/资源根
- 触发条件：工作区存在指向外部敏感目录的符号链接，且 Markdown 引用该链接。
- 复现步骤：在工作区创建 symlink 指向外部目录，引用相对文件或图片。
- 复现结果：lexical 路径可能被判定为工作区内，实际 realpath 在外部。
- 实际表现：普通 `../` 会被拒绝，但 symlink 边界未闭合。
- 预期表现：敏感文件边界按 realpath 和明确的用户授权目录判断。
- 影响范围：本地文件读取和 Webview 资源根。
- 安全影响：潜在本地文件泄露，仅限用户已经拥有创建/打开工作区 symlink 的场景。
- 业务影响：过度收紧会破坏合法 monorepo/资源链接，需权衡。
- 数据影响：可能读取工作区外图片/文本；当前图片仅允许图片扩展名，但仍可能泄露文件存在和内容。
- 性能影响：realpath 大量调用会增加 IO。
- 利用难度：中，需要本地文件系统准备。
- 是否可远程利用：否。
- 是否需要登录权限：否。
- 修复建议：对最终读取目标使用 `realpath`，同时允许用户显式配置可信外部资源根；拒绝未授权 symlink。
- 短期止血方案：不要在包含不可信 symlink 的工作区打开不可信 Markdown。
- 长期治理方案：统一 realpath 沙箱策略并缓存目录边界。
- 验证方式：symlink 外部目录、合法 workspace symlink 和跨平台路径测试。
- 回归测试要求：普通相对链接、Windows 分隔符、合法资源根仍可用。
- 修复优先级：P2。
- 修复依赖：需要确认用户对外部图片/主题目录的合法使用场景。
- 当前残余风险：`.8` 保留 lexical 检查，未宣称已修复。

## 十三、可接受的残余风险

- 宿主 macOS Code 的 SIGABRT 不代表用户 IDE 一定失败，但当前会话无法把它作为本机真实验收证据。
