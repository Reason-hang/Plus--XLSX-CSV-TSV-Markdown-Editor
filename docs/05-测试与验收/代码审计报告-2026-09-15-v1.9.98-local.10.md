## 五、功能逻辑问题清单

### AUDIT-001：可选字符串字段存在但类型错误时被放行

问题编号：AUDIT-001  
问题标题：`validateString` 对存在的可选字段未执行类型拒绝  
风险等级：P2  
问题类型：输入校验逻辑缺口  
置信度：高  
影响模块：`src/shared/webviewMessageSchema.ts` 的 `insertControl`、富文本颜色等字段  
故障根因：`validateString(value, field, maxBytes, false)` 在 `value` 不是字符串时直接返回 `pass()`；它无法区分“字段不存在”和“字段存在但类型错误”。  
代码证据：第 119-123 行的 `typeof value !== 'string'` 分支在 `required=false` 时放行。  
文件路径：`src/shared/webviewMessageSchema.ts`  
代码行号：119-123  
调用链：Webview → `onDidReceiveMessage` → `validateWebviewMessage` → `validateOperation`/`validateRichEdit` → 业务保存分支。  
触发条件：发送 `insertControl.defaultValue=123` 或 `richEdit.runs[].color=123` 等存在但类型错误的字段。  
复现步骤：构造上述消息并调用 `validateWebviewMessage(message, 'spreadsheet')`。  
复现结果：消息可能返回 `{ ok: true }`，随后业务代码将错误值转换或忽略。  
实际表现：schema 没有完整履行“字段存在时必须类型正确”的约定。  
预期表现：可选字段缺失时通过，字段存在但类型错误时拒绝。  
影响范围：当前受影响的是可选字符串字段；不直接绕过文件路径 containment。  
安全影响：可造成业务分支对未经严格验证的数据进行隐式转换，扩大输入面。  
业务影响：错误控件默认值或样式字段可能被静默改写。  
数据影响：低；当前代码不会因该项直接写入任意路径。  
性能影响：低。  
利用难度：低；只需构造 Webview 消息。  
是否可远程利用：不适用，插件本地 Webview 攻击面。  
是否需要登录权限：不需要。  
修复建议：将“缺失”与“存在但错误”分开判断；可选字段仅在 `value === undefined` 时通过。  
短期止血方案：在业务分支继续保留现有安全默认值，不将错误类型直接写入文件。  
长期治理方案：为共享 schema 增加可选字段类型参数测试，禁止各 provider 自行隐式转换。  
验证方式：增加 `defaultValue`、`color` 为数字/对象时的拒绝测试。  
回归测试要求：运行 TypeScript、security、Extension Host 和正常控件插入回归。  
修复优先级：发布前修复。  
修复依赖：无。  
当前残余风险：在修复前保留低概率输入污染风险。

### AUDIT-002：保存失败原因未向用户明确呈现

问题编号：AUDIT-002  
问题标题：StyleStorage 容量拒绝和其他保存异常最终只显示通用 toast  
风险等级：P2  
问题类型：错误反馈与状态闭环缺口  
置信度：高  
影响模块：表格 Webview 保存结果、`StyleMetadataLimitError` 用户反馈  
故障根因：Extension Host 已把 `String(err)` 放入 `saveResult.error`，但 Spreadsheet Webview 的失败分支固定显示 `Error saving` 或 `Autosave failed`，没有使用错误字段。  
代码证据：Provider 第 2396-2397 行发送 `error`；Webview 第 7712-7715 行丢弃 `message.error`。  
文件路径：`src/spreadsheetEditorProvider.ts`、`src/webviews/spreadsheet/spreadsheetWebview.ts`  
代码行号：Provider 2396-2397；Webview 7712-7715  
调用链：表格编辑 → `assertMetadataWithinLimits` → `StyleMetadataLimitError` → `saveResult` → `showToast`。  
触发条件：样式 cells、merges 或 JSON 字节数超过阈值。  
复现步骤：提交超出 `STYLE_STORAGE_LIMITS` 的样式元数据并观察 Webview。  
复现结果：主文件不应写入，但用户只看到通用保存失败提示。  
实际表现：数据保护动作存在，错误原因不可见。  
预期表现：显示“样式元数据超过限制”等明确、可操作的错误信息。  
影响范围：主要影响 CSV/TSV 样式保存和 XLSX 保存异常；不改变已拒绝写入的事实。  
安全影响：低；主要是可观测性和恢复路径问题。  
业务影响：用户无法判断是容量限制、文件冲突还是权限错误。  
数据影响：拒绝时主文件应保持不变；用户可能重复尝试。  
性能影响：低。  
利用难度：不适用。  
是否可远程利用：不适用。  
是否需要登录权限：不适用。  
修复建议：优先显示受控的 `message.error`，对内部错误做长度限制；保留 `errorCode` 便于定位。  
短期止血方案：Provider 已在写文件前校验容量，确保失败不污染主文件。  
长期治理方案：统一 Extension Host → Webview 的错误 schema，区分用户提示与诊断日志。  
验证方式：超限保存时断言主文件哈希不变、workspaceState 不变且 Webview 收到明确提示。  
回归测试要求：CSV、TSV、XLSX 正常保存和超限保存都要覆盖。  
修复优先级：发布前修复。  
修复依赖：无。  
当前残余风险：用户体验和排障效率受影响，但当前实现不会静默截断或覆盖旧元数据。

## 六、安全问题清单

### AUDIT-003：列操作索引使用错误的坐标上限

问题编号：AUDIT-003  
问题标题：`insertColumn*`/`deleteColumn` 的 `index` 使用行上限校验  
风险等级：P2  
问题类型：坐标边界校验不精确  
置信度：高  
影响模块：Spreadsheet Webview 结构操作  
故障根因：`validateOperation` 把行操作和列操作合并到同一分支，并统一使用 `WEBVIEW_LIMITS.maxCoordinate`；列操作应使用 `maxColumnCoordinate`。  
代码证据：第 196-198 行；`maxCoordinate=1,048,576`，`maxColumnCoordinate=16,384`。  
文件路径：`src/shared/webviewMessageSchema.ts`  
代码行号：196-198  
调用链：Webview 结构操作 → `validateWebviewMessage` → Spreadsheet Provider 的 `spliceColumns`。  
触发条件：发送 `insertColumnRight` 或 `deleteColumn` 且 `index > 16,384`。  
复现步骤：构造 `operations: [{type:'insertColumnRight', index: 100000}]` 的保存消息。  
复现结果：消息层可能通过，后续依赖 ExcelJS 的行为；未满足列坐标范围契约。  
实际表现：列索引上限比 Excel 工作表列上限宽。  
预期表现：列操作在 schema 层直接拒绝。  
影响范围：结构列操作；普通单元格 `col` 校验已经使用列上限。  
安全影响：可能触发不必要的结构扩展或异常路径。  
业务影响：恶意或异常消息可能使列操作结果与用户意图不一致。  
数据影响：正常输入不受影响；超范围输入应被拒绝而不是交给库处理。  
性能影响：极端索引可能增加 ExcelJS 处理成本。  
利用难度：低。  
是否可远程利用：不适用。  
是否需要登录权限：不需要。  
修复建议：按操作轴分别使用行/列上限，并增加 16,385 列操作拒绝测试。  
短期止血方案：当前仍有全局消息大小、操作条数和 ExcelJS 后续边界作为二次限制。  
长期治理方案：把 row/column/index/merge 的轴约束抽成共享坐标校验器。  
验证方式：校验列操作 `index=16,385` 为失败，`index=16,384` 为通过。  
回归测试要求：XLSX、CSV、TSV 结构操作正常回归。  
修复优先级：发布前修复。  
修复依赖：无。  
当前残余风险：修复前存在超出 Excel 列范围的异常操作输入窗口。
