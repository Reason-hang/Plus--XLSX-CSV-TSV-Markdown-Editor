# Markdown 预览编辑数据保真与目录锚点审计报告

> 审计日期：2026-09-20
>
> 审计范围：Markdown “预览编辑”保存链路、代码块和 Mermaid 保真、正文目录锚点跳转
>
> 审计基线：`6d1c537fd4ab230b52c93f0fa611f087498a7c8f`，`1.9.98-local.16`
>
> 现场样本：用户本机 Markdown 文档 `格局[吴军]-篇章深度总结与XMind导图.md`；该文件不属于仓库，未被本次审计修改。
>
> 审计性质：源码静态追踪 + 已损坏样本现场取证；尚未实施修复。

## 1. 一页式结论

发现一项 **P1 数据保真故障**：Markdown “预览编辑”把已经渲染和增强过的 HTML 交给 `Turndown` 再保存为 Markdown。这个过程不是无损的反向转换：Mermaid 原始围栏源码已经在 DOM 中变成 SVG/CSS，代码块也被包装为语言标签、复制按钮和逐行节点。因此保存会把渲染产物或工具栏文字写入用户源文件，无法保留 ` ```mermaid `、` ```text ` 及 Tab 缩进的原始布局。

发现一项 **P2 目录锚点正确性故障**：手写目录前十个 URL 片段并不等于插件为实际标题生成的 `id`；浏览器找不到目标时插件放任原生默认行为，表现为跳到文档开头。第 106 行之所以正常，是因为它的片段恰好与标题 ID 完全一致。

| 优先级 | 编号 | 问题 | 影响 | 当前结论 |
| --- | --- | --- | --- | --- |
| P1 | MD-PE-001 | 预览 HTML 经 Turndown 回写 Markdown 破坏结构 | 用户文件数据、Mermaid、围栏代码、Tab 排版 | 已由现场损坏文件和调用链确认 |
| P2 | MD-TOC-001 | 手写目录片段不匹配标题 ID 时跳到顶部 | 文档导航不可用、用户误以为目录已失效 | 已由行 95–106 与标题对照确认 |

## 2. 现场证据与范围

### 已核实的现场证据

样本文档在审计时已出现以下内容，均不是原始 Markdown 语义的一部分：

- 第 11 行为以 `#mermaid-...` 开头的大段 Mermaid 渲染 CSS，而非 ` ```mermaid ` 围栏源码。
- 第 138–140 行出现 `text`、`复制`，对应插件代码块语言标签和复制按钮的可见文字。
- 第 142–144 行仍是 ` ```text ` 围栏，但第 143 行原有多行 Tab 缩进内容已坍缩为一个物理行，原布局不可由现有内容可靠还原。
- 目录第 95–105 行的链接片段省略了实际标题中的中文标点和括号限定语；第 106 行的片段与 `## 全书本质总结与产品经理启发` 完全相同，因此只有第 106 行正常跳转。

### 未覆盖范围

- 未修改、恢复或从版本历史还原样本文档；该动作会覆盖用户文件，必须另行明确授权。
- 未在本轮将修复打包、安装或发布。
- 未宣称所有 Markdown 结构都已穷尽；本报告证明现有回写策略对 Mermaid 和围栏代码不安全。

## 3. 模块与调用链

```text
原始 Markdown
  -> markdown-it 渲染
       -> Mermaid fence: <div class="mermaid">源码</div>
       -> Mermaid run(): DOM 改为 SVG + style/CSS
       -> 普通 fence: code-block 包装 + 语言标签 + 复制按钮 + 逐行节点
  -> 用户在 Preview Edit 中编辑 contenteditable 预览
  -> performSave()
       -> clone preview DOM
       -> 仅删除 table-hover-tools / heading-anchor
       -> Turndown(clone.innerHTML)
       -> saveMarkdown 原子写入用户源文件
```

`src/mdEditorProvider.ts` 的原子写入和保存前指纹校验只保证“不与外部修改冲突、写入不半截”；它会正确地把 Webview 传来的文本写入磁盘，无法识别该文本是否已在前端失真。

## 4. Critical 问题

本次范围未发现远程代码执行、权限绕过或不可恢复的批量删除。Markdown 文件本身可能已被错误保存而受损，因此 MD-PE-001 定为 P1，而非以“已有版本快照”降低为一般显示问题。

## 5. 功能正确性问题

### P1：MD-PE-001 — Preview Edit 以渲染 DOM 反向生成 Markdown，无法保持结构化源文本

- **位置**：`src/webviews/md/mdWebview.ts:747-780`、`1092-1137`、`1214-1254`；`src/mdEditorProvider.ts:596-615`。
- **证据**：Mermaid 围栏被渲染为 `.mermaid` 容器后执行 Mermaid；普通围栏被包装为 `.code-block`、`text` 和 `复制`。保存时仅移除两个局部 UI 节点，随后对整棵预览 DOM 调用 `turndownService.turndown()`；Provider 将返回文本原样写入。
- **影响**：保存任意 Preview Edit 修改时，可能将 Mermaid CSS/SVG、代码块 UI 文本或格式扁平化内容写入原 Markdown。原文件的人工排版、Tab 缩进、围栏语言和语法均可能丢失。
- **根因**：渲染 DOM 不是 Markdown 源码的双向模型。Mermaid、语法高亮、代码复制控件、表格编辑装饰以及浏览器 contenteditable 修改均缺少可逆的 source map；`Turndown` 是 HTML→Markdown 转换器，并不知道每个节点来自哪段原始源码。
- **为什么现有保护无效**：`cloneNode()` 只避免直接修改当前预览，不恢复源码；删除 `.table-hover-tools`/`.heading-anchor` 只覆盖两种 UI；原子写入和哈希校验不判断内容语义。
- **推荐修复（P0，保真优先）**：在 Preview Edit 保存前建立“源文本可安全回写”门禁。当前最小安全版本应至少拒绝包含任何围栏代码（` ``` `、`~~~`，包括 Mermaid）的 Preview Edit 保存，并以简体中文提示改用“编辑文件”或“分栏编辑”。更稳妥的长期方案是按 Markdown token/source range 进行受限编辑和最小文本补丁，完全移除“整棵渲染 DOM → Turndown → 覆盖源文件”的通用保存路径。
- **不建议的方案**：继续补充要从 clone 中删除的 CSS、按钮或 SVG 选择器。这只能追上已知节点，无法使不可逆转换成为无损编辑器，且会不断遗漏新渲染器。
- **验收**：
  1. Mermaid、`text`、JSON、表格、嵌套列表等围栏文件进入 Preview Edit 后，保存必须拒绝且磁盘文件 SHA-256 不变。
  2. 拒绝后不新增版本快照、不改变 `currentContent`、不关闭编辑模式。
  3. “编辑文件”和“分栏编辑”对同一文件正常保存；围栏行数、Tab、语言标记与 SHA-256 按预期变化。
  4. 完整受限编辑方案实施后，覆盖 Mermaid、围栏、HTML、KaTeX、表格和链接的端到端保存回归。

### P2：MD-TOC-001 — 手写正文目录的片段与生成标题 ID 不匹配时无受控回退

- **位置**：`src/webviews/md/mdWebview.ts:782-799`、`4101-4129`。
- **证据**：标题 ID 来自完整标题文本的 `slugify()`，保留中文全角标点及括号内限定内容；样本文档第 95–105 行的 URL 片段把标题缩短为“前言从态度到格局”“第一章人生的格局”等，均找不到对应 ID；第 106 行完全匹配，故正常。
- **影响**：用户手写或其他工具生成的目录，若与本插件 ID 规则不完全一致，会跳转到顶部或没有跳转；此问题不破坏源文件，但影响长文档导航。
- **根因**：点击监听对 `#` 开头的内部链接直接返回，让浏览器自行寻找 ID；没有“找不到目标”的显式处理、错误提示或安全的兼容解析。
- **推荐修复（P1）**：始终拦截内部锚点。先按解码片段做精确 ID 查找；失败时仅允许“唯一匹配”的保守回退：以链接文字和标题文字做统一规范化，并允许移除标题末尾唯一的括号限定语后精确匹配。没有唯一结果时不滚动到顶部，显示“未找到唯一目录目标”的中文提示。
- **边界**：不得做任意前缀模糊匹配，也不得“取第一个相似标题”；同名/近似标题必须拒绝而非跳错。
- **验收**：第 95–106 行均跳到其唯一标题；重复标题和不存在标题不会跳到错误位置；插件左侧自绘大纲既有跳转不回归；外部 HTTP/相对文件链接仍走原有路径。

## 6. 安全审查结果

- P1 修复不得通过注入未清洗 HTML、开放 Webview 脚本权限或降低 CSP 来“保留格式”。
- 锚点回退只在已渲染 preview 内的标题集合中查找，不能用 fragment 构造 CSS 选择器；应使用 `getElementById` 或经 `CSS.escape` 的受控选择器。
- 保存拒绝必须发生在向 Extension Host 发送 `saveMarkdown` 消息之前，避免版本快照和磁盘产生副作用。

## 7. 性能与稳定性审查结果

- 预览编辑的受控保存门禁是常数级/线性文本检查，风险远低于全量 HTML 反转换。
- 锚点解析只在点击时遍历有限标题集合，可缓存标题标准化结果；无需在每次输入时计算。
- 长期 source-range 编辑应按最小文本片段补丁，避免重新序列化整份文档。

## 8. 架构与可维护性审查结果

当前 Preview Edit 将“渲染层”同时当成“数据模型”和“保存来源”，违反内容、渲染、编辑意图分离。短期门禁可阻断数据损坏；长期应明确两种编辑能力：

1. **源码编辑**：以 textarea 为唯一真相，保留 Markdown 格式。
2. **受限可视编辑**：只允许有明确 source range 的文本或表格单元格进行最小补丁，无法映射的节点只读。

这比维护一份逐步增长的 DOM 清理清单更可验证、可回退。

## 9. 数据一致性审查结果

MD-PE-001 的保存链路可通过 Provider 原子写入成功完成，因此它是“原子地写入了错误内容”，不是写入失败。修复的第一验收指标必须是被拒绝时原文件哈希不变；不能只测 Webview 里的 toast 或按钮状态。

## 10. 修复路线与优先级

1. **P0（下一补丁）**：阻断含围栏代码/Mermaid 的 Preview Edit 保存；用现有提示机制说明转用源码编辑或分栏编辑；添加“拒绝前不得 postMessage/saveVersionSnapshot”的测试。
2. **P1（同一版本可完成）**：内部锚点精确查找 + 唯一的链接文字/标题规范化回退；添加实际第 95–106 行形式的回归用例。
3. **P1（修复后审计）**：对 Preview Edit 所有 `contenteditable` 保存入口重跑数据保真审计，并用独立临时副本验证文件哈希、围栏内容、Mermaid 源码与目录跳转。
4. **长期独立版本**：实现 source range 驱动的受限可视编辑；在此之前不承诺 Preview Edit 是“任意 Markdown 无损 WYSIWYG 编辑器”。

## 11. 阻塞项与需要补证的事实

| 待证事实 | 重要性 | 证实方法 |

## 12. 观察项与反证条件

以下任一事实成立，需重新评估本报告的根因或优先级：

1. 证明受损文件在使用 Preview Edit 前已包含 Mermaid CSS、`text`、`复制` 或单行化 Tab 内容。
2. 证明 `performSave()` 未在故障操作后执行，且另有独立写入者把渲染 HTML 保存回磁盘。
3. 证明第 95–105 行 URL 片段在运行时实际存在同名 `id`，但被其他脚本、CSP 或 IDE 内核阻止跳转。

## 13. 可接受风险与用户操作建议

在 P0 修复发布前，不要使用“预览编辑”保存包含 Mermaid、` ```text `、其他围栏代码或依赖 Tab 排版的文档。需要编辑时请使用“编辑文件”或“分栏编辑”，并在任何 Preview Edit 保存前保留文件副本。该建议是临时止损，不是把用户责任替代为产品修复。

## 14. 审计结论

本次问题不是上游 Markdown 文件写法错误，也不能靠 CSS 调整解决。根因是 Preview Edit 采用了不可逆的“渲染 DOM 反序列化”保存模型；目录问题则是未匹配锚点被放任给浏览器默认处理。建议先以 P0 数据保真门禁停止继续损坏用户文件，再以唯一匹配的锚点回退恢复目录可用性，最后独立设计 source-range 可视编辑，而不是继续扩展 Turndown 清理规则。
