# XLSX、CSV、TSV 与 Markdown Editor 代码审计报告（修复复核版）

审计日期：2026-08-31
审计对象：XLSX、CSV、TSV & Markdown Editor 本地补丁版
当前版本：1.9.98-local.3
上游基线：v1.9.97
审计性质：基于历史审计报告的当前源码复核、故障修复与回归验证

## 一、审计结论

本报告以用户提供的历史报告（针对 1.9.98-local.2）作为问题线索，以当前仓库源码、测试脚本、构建结果和打包结果作为最终事实依据。历史报告未绑定提交 SHA，因此不能直接把历史行号视为当前代码证据。

本轮已修复或缓解的重点问题：

- Markdown 原始 HTML 进入预览 DOM 的 XSS 风险：增加渲染后 HTML 清理、危险 URL 和事件属性清理、CSP nonce；保留 Mermaid 所需的 unsafe-eval，并移除 script unsafe-inline。
- 电子表格普通单元格、富文本和链接属性的 HTML 注入风险：统一转义显示值，富文本仅保留明确允许的标签和颜色格式。
- 保存和版本恢复的无提示覆盖风险：增加 SHA-256 文件指纹检查，并在本地文件写入时采用同目录临时文件加原子替换。
- Markdown 历史记录把完整正文集中写入单个 JSON 的增长风险：改为独立快照文件加索引，并增加时间、条数和总容量边界。
- CSV UTF-8 BOM、稀疏 XLSX、转换后样式失败被误报为整体转换失败、模块级分隔符状态污染等问题。
- 外置主题 CSS 的资源 URL 绕过、外部文件路径越界和预览自定义样式安全边界问题。

当前仍需关注的事项：

- 依赖在线审计已经完成：当前锁文件仍有 8 项漏洞（4 low、3 moderate、1 high、0 critical）。运行时公式渲染已移除无自动修复的 `markdown-it-katex`；当前 high 项来自测试工具链，`exceljs`、`mocha` 为直接 moderate，`vscode-test` 为直接 low。
- 已执行不带 `--force` 的 `npm audit fix --package-lock-only`，并更新了可安全更新的锁文件依赖；测试工具链的剩余漏洞未强行降级或替换，避免引入不必要的构建回归。
- Markdown 和表格编辑器仍使用 CustomReadonlyEditorProvider，原生 dirty、backup、崩溃恢复能力不是完整的 VS Code 原生编辑器语义。
- 文件指纹检查与实际写入之间仍存在极短的 TOCTOU 窗口；本工具定位为个人或小型工具，当前方案已显著降低误覆盖风险，但不是并发数据库事务。
- CSS 的样式属性采用危险 token 拦截而非完整 CSS 沙箱；外置主题文件仍应视为用户本人信任的本地配置。

综合结论：历史 P0 代码级问题已完成修复，当前没有已确认的 P0 级开放缺陷；运行时公式 high 风险依赖已移除，但测试工具链仍有 1 项 high、3 项 moderate 和 4 项 low。当前版本可在个人可信文档场景继续使用，公开发布前仍需完成工具链依赖处置或正式豁免，以及三套 IDE 的真实安装验收。

- A：当前源码、可执行测试或构建输出直接证明。
- B：静态调用链和配置分析支持，但仍需要真实 IDE 或外部环境确认。

### 3.3 主要调用链

Markdown：

~~~text
Markdown 文件
  -> mdEditorProvider 读取与生成 webview
  -> mdWebview markdown-it / Mermaid 渲染
  -> sanitizeRenderedMarkdownHtml
  -> preview.innerHTML
  -> postMessage 保存或恢复
~~~

表格：

~~~text
XLSX/CSV/TSV 文件
  -> fileConversionService / spreadsheetEditorProvider
  -> spreadsheetRenderComponent
  -> escapeHtml / 富文本允许列表
  -> webview DOM
  -> hash 检查
  -> atomicFile 写入
~~~

## 四、问题清单与修复复核

## AUDIT-P0-001：Markdown 原始 HTML 导致预览 DOM XSS

- 风险等级：P0（历史问题，当前代码级已修复）
- 问题类型：安全、渲染边界、消息链路
- 影响模块：Markdown 预览、Markdown 保存消息、Mermaid
- 故障根因：历史实现把 markdown-it 产生的 HTML 直接写入预览 DOM，并允许原始 script、事件属性、危险 URL 或嵌入元素进入 webview。
- 历史证据：历史报告记录 html: true、preview.innerHTML、CSP unsafe-inline 和保存消息链路的组合风险。
- 当前代码证据：src/webviews/md/mdWebview.ts 的 sanitizeRenderedMarkdownHtml 在写入 preview.innerHTML 前清理危险元素、属性和 URL；Markdown webview 使用 CSP nonce；Mermaid 使用 strict 安全级别。
- 触发条件：Markdown 内容包含 script、onerror、javascript URL、srcdoc、外部嵌入元素或恶意 SVG/HTML。
- 当前复现结果：安全回归测试通过；危险元素和属性被移除，允许的 mark 和普通安全行内样式仍可渲染。
- 预期表现：不执行脚本、不发起非允许资源请求、不修改宿主文件；合法 Markdown 和高亮正常显示。
- 安全影响：当前已阻断代码级 XSS 主路径；CSP 仍保留 unsafe-eval，仅用于 Mermaid，不能将该配置解释为完整 XSS 防护。
- 业务影响：恶意文档不能通过预览直接接管 webview 消息或诱导覆盖文件。
- 数据影响：当前没有发现由该路径直接写入任意文件的证据。
- 利用难度：历史上中等；修复后需要绕过清理器、CSP 和宿主边界，当前未发现可复现绕过。
- 修复内容：新增渲染 HTML 清理；移除 script、style、iframe、object、embed、base、meta、link、portal、form、foreignObject；移除事件属性、srcdoc、srcset；仅允许 http、https、mailto 和限定的 raster data image；拦截 style 中的 url、@import、expression、behavior、-moz-binding、javascript。
- 验证方式：执行 npm run verify:security，并在三套 IDE 中分别打开包含恶意 HTML 和合法 mark 的 Markdown。
- 回归测试要求：覆盖原始 HTML、Markdown 链接、图片、Mermaid、mark、表格、保存和刷新。
- 修复优先级：已完成；继续保持 P0 回归用例。
- 当前残余风险：样式属性不是完整 CSS 解析器；CSP 的 unsafe-eval 需要持续评估 Mermaid 版本和实现变化。

## AUDIT-P0-002：电子表格单元格和富文本进入 innerHTML

- 风险等级：P0（历史问题，当前代码级已修复）
- 问题类型：安全、数据渲染
- 影响模块：spreadsheetRenderComponent、XLSX/CSV/TSV 预览
- 故障根因：历史普通单元格值和富文本片段直接拼接 HTML，未区分用户数据与可信标签。
- 历史证据：历史报告指出普通 cellData.value 进入 innerHTML，富文本和属性链路也存在注入可能。
- 当前代码证据：src/shared/htmlUtils.ts 提供统一 HTML/属性转义；src/spreadsheet/cellValue.ts 和 spreadsheetRenderComponent.ts 对普通值、富文本、超链接、颜色和 style 属性执行转义或允许列表过滤。
- 触发条件：单元格内容包含 HTML、事件属性、引号、尖括号、javascript URL 或非法富文本标签。
- 当前复现结果：安全回归测试覆盖普通值 XSS、富文本允许列表、属性注入，以及 0、false、公式结果 0。
- 预期表现：数据按文本显示；只有程序生成的 b、i 和精确允许的颜色 span 生效。
- 安全影响：当前已阻断主要的 cell-to-DOM XSS 路径。
- 业务影响：正常表格内容、数字、布尔值、公式结果和富文本不应丢失。
- 数据影响：显示层转义不改变源文件内容。
- 修复内容：统一 escapeHtml 和 escapeAttribute；富文本采用明确允许列表；链接协议和颜色值受限；样式属性不再信任原始单元格内容。
- 验证方式：npm run verify:security；补充人工打开含特殊字符、链接和富文本的 XLSX、CSV、TSV。
- 回归测试要求：空值、0、false、公式 0、引号、换行、中文、HTML 标签和超长文本。
- 修复优先级：已完成。
- 当前残余风险：如果未来新增其他 innerHTML 拼接点，必须复用同一套转义和允许列表，不能重新直接信任单元格内容。

## AUDIT-P1-001：Markdown 公式渲染依赖替换

- 风险等级：P1（历史问题，当前代码级已修复）
- 问题类型：第三方依赖、安全供应链
- 影响模块：Markdown 数学公式渲染
- 故障根因：历史运行时直接使用无维护修复版本的 `markdown-it-katex@2.0.3`，且它会引入旧版 KaTeX 依赖。
- 当前证据：已移除 `markdown-it-katex` 依赖，新增本地 `src/webviews/md/markdownItKatex.ts`，直接调用当前锁定的 `katex`，并强制 `trust: false`；`verify:security` 已覆盖 `$...$`、`$$...$$` 的公式渲染和脚本输出检查。移除后执行 `npm audit --json --package-lock-only`，结果为 `8 vulnerabilities (4 low, 3 moderate, 1 high, 0 critical)`，不再包含 `markdown-it-katex`。
- 触发条件：加载包含数学公式的 Markdown，或公式输入包含 KaTeX 的受限命令。
- 当前表现：本地插件仍支持原有行内和块级数学公式；渲染失败时按文本输出，公式输出随后仍经过 Markdown HTML 清理。
- 预期表现：公式渲染使用当前 KaTeX 版本，不引入旧版 `markdown-it-katex` 依赖和可执行 HTML。
- 修复建议：持续锁定 `katex` 版本并定期执行 SCA；如果将来改变公式渲染方案，必须保留 `trust: false` 和公式回归用例。
- 短期止血：不打开来源不可信且包含复杂公式的文档；当前代码级净化、CSP 和 KaTeX `trust: false` 共同降低输入风险。
- 长期治理：锁定依赖版本，定期执行 SCA，记录漏洞、是否受影响、升级版本和回归结果。
- 验证方式：`npm run verify:security`、KaTeX 公式回归、`npm audit --audit-level=high --package-lock-only`。
- 修复优先级：已完成；保留 P1 回归用例。
- 当前残余风险：KaTeX 本身的输入兼容性和未来版本变化仍需回归；当前 high 审计项已转为测试工具链的 `serialize-javascript`。

## AUDIT-P1-002：Markdown 版本历史集中存储导致增长和写入压力

- 风险等级：P1（已修复）
- 问题类型：数据一致性、性能、资源管理
- 影响模块：mdEditorProvider、版本历史
- 故障根因：历史实现把完整正文放在单个 JSON 数组中，短时间频繁写入；大文档会造成重复读写和索引膨胀。
- 当前代码证据：Markdown 历史改为独立 md 快照加 index.json；保存间隔为 30 秒；最多 200 条、总容量 50 MiB，并使用原子写入。
- 触发条件：持续编辑大 Markdown、快速保存、历史索引损坏或旧格式迁移。
- 当前表现：旧格式按受限条目迁移；快照和索引分离；超出边界时按时间和容量清理。
- 预期表现：历史可恢复，单次写入成本有界，异常退出不会产生半写索引。
- 修复内容：独立快照、上限、受控迁移、原子索引写入、失败日志。
- 验证方式：安全回归静态检查；人工编辑大文档并观察快照数量、目录大小和恢复结果。
- 修复优先级：已完成。
- 当前残余风险：表格编辑器仍有独立历史实现，尚未统一使用同一套 200 条/50 MiB 策略；应作为后续一致性治理项。

## AUDIT-P1-003：保存和恢复可能静默覆盖外部修改

- 风险等级：P1（已缓解，仍有架构残余）
- 问题类型：数据一致性、并发、保存流程
- 影响模块：mdEditorProvider、spreadsheetEditorProvider
- 故障根因：历史保存路径没有在写入前确认磁盘文件是否仍是当前打开版本。
- 当前代码证据：Markdown 和表格 provider 维护 lastKnownFileHash，在保存、恢复等关键写入前执行 assertFileUnchanged；本地文件使用 atomicFile。
- 触发条件：编辑器打开文件后，外部编辑器、同步软件或脚本修改同一文件，再从当前 webview 保存。
- 当前表现：发现 SHA-256 不一致时拒绝写入并报告冲突；正常写入通过同目录临时文件替换。
- 预期表现：不应静默覆盖外部修改；用户可先重新加载或人工合并。
- 修复内容：文件指纹检查、保存后更新指纹、恢复前再次检查、原子写入。
- 验证方式：打开文件后用外部进程修改，再触发保存和恢复；确认写入被阻止。
- 修复优先级：P1，当前可交付；后续可改进为更明确的冲突对话框。
- 当前残余风险：检查与写入之间仍有 TOCTOU 窗口；原子替换不等于分布式锁或事务。

## AUDIT-P2-001：转换后样式失败被误报为整体转换失败

- 风险等级：P2（已修复）
- 问题类型：功能逻辑、错误语义
- 影响模块：extension.ts、fileConversionService
- 故障根因：文件转换和目标样式应用共用错误状态，样式步骤失败时把已经生成的有效目标文件误报为整体失败。
- 触发条件：CSV/TSV 转 XLSX 成功，但后续样式复制或应用失败。
- 当前表现：转换文件保留，提示明确说明“转换成功但样式应用失败”，而不是误报为没有产物。
- 预期表现：用户能区分核心转换结果和可选样式结果。
- 修复内容：拆分 conversion 和 style 阶段；仅在样式成功后清理临时样式状态；针对目标文件存在情况给出警告。
- 验证方式：模拟样式阶段失败，确认目标文件仍可打开且提示准确。
- 修复优先级：已完成。

## AUDIT-P2-002：直接截断写文件导致半写文件

- 风险等级：P2（已修复）
- 问题类型：可靠性、数据完整性
- 影响模块：配置、主题、历史、Markdown/PDF 输出、XLSX 保存
- 故障根因：直接 writeFile 在进程中断或磁盘异常时可能留下截断文件。
- 当前代码证据：src/shared/atomicFile.ts 以同目录随机临时文件写入，再 rename 替换；调用方已覆盖关键本地文件写入。
- 触发条件：写入过程中进程崩溃、强制退出、磁盘空间耗尽或系统异常。
- 当前表现：临时文件失败时清理；原目标文件通常保持不变。
- 预期表现：关键文件不应因为一次失败写入变为空文件或半个 JSON。
- 修复优先级：已完成。
- 当前残余风险：未执行 fsync，不能承诺断电级持久性；个人工具范围内接受该残余风险。

## AUDIT-P2-004：CustomReadonlyEditorProvider 缺少完整原生编辑器语义

- 风险等级：P2（架构残余）
- 问题类型：架构、恢复、用户体验
- 影响模块：Markdown、XLSX/CSV/TSV 自定义编辑器
- 根因：provider 采用 CustomReadonlyEditorProvider，保存和备份由扩展自定义处理。
- 风险：原生 dirty 状态、backup、崩溃恢复、关闭前确认可能与 VS Code TextDocument 不完全一致。
- 当前补偿：版本快照、文件指纹、原子写入、错误日志。
- 建议：不为个人工具立即引入大规模重构；若出现实际丢失或恢复问题，再评估迁移到 CustomEditorProvider 或原生 DocumentModel。
- 当前残余风险：仍需在 VS Code、Cursor、Antigravity 中人工验证关闭窗口、异常退出、外部修改和恢复流程。

## AUDIT-P2-005：模块级 csvSeparatorOverride 状态污染

- 风险等级：P2（已修复）
- 问题类型：并发、配置、数据一致性
- 故障根因：历史模块变量在不同文件转换任务之间共享，可能被上一次任务污染。
- 当前代码证据：已移除模块级 setter，分隔符在调用链中按配置和当前任务读取。
- 触发条件：连续处理不同分隔符的 CSV/TSV，或同时触发多个转换任务。
- 当前表现：任务之间不再依赖共享可变覆盖值。
- 验证方式：安全回归静态检查确认不存在 csvSeparatorOverride；分别转换逗号、分号和制表符文件。
- 修复优先级：已完成。

## AUDIT-P3-001：UTF-8 BOM 与稀疏 XLSX 资源边界

- 风险等级：P3（已修复）
- 问题类型：数据兼容、性能、资源管理
- 故障根因：历史分隔文件可能把 BOM 当作首字段内容；稀疏 XLSX 的有效范围可能被极端元数据放大。
- 当前代码证据：delimited read 去除 UTF-8 BOM；XLSX 转换限制行、列、有效范围和稀疏比例。
- 触发条件：带 BOM 的 CSV/TSV，或有效单元格很少但 declared range 极大的 XLSX。
- 当前表现：BOM 不进入首字段；异常稀疏范围被拒绝并给出错误。
- 修复优先级：已完成。

## AUDIT-P3-002：主题 CSS 资源 URL、外部路径和工作区边界

- 风险等级：P3（已修复，符号链接风险待验证）
- 问题类型：安全、配置、路径边界
- 影响模块：markdownThemeService、mdEditorProvider、外置主题
- 故障根因：历史拦截只覆盖直接 url，可能遗漏 url(var(...))；外部相对文件和工作区路径需要边界校验。
- 当前代码证据：已拦截直接 URL 和 url(var(...))；外部 URI 使用 allowlist；相对文件要求位于允许的工作区边界。
- 触发条件：主题中使用远程资源、变量拼接 URL、绝对路径或工作区外相对路径。
- 当前表现：危险资源样式拒绝加载；不允许的 URI 和越界路径被拒绝。
- 验证方式：用外部 CSS 测试 url、url(var())、workspace 外路径和允许路径。
- 当前残余风险：符号链接解析和真实路径边界仍需在目标系统人工验证；不要把主题文件目录设为包含敏感文件的宽泛目录。

## 五、架构与跨模块审查结论

### 5.1 分层与信任边界

- extension host 负责文件、配置、路径、哈希、原子写入和消息入口。
- webview 负责渲染和交互，不应直接信任 Markdown、表格单元格或外部主题内容。
- shared 层承载转义、文件指纹、原子写入、路径和主题安全策略。
- 当前不存在必须立即拆分的大型循环依赖；新增安全逻辑集中在 shared 和渲染入口，符合单向依赖。

### 5.2 状态机与幂等性

- 打开、编辑、保存、恢复、外部修改、刷新之间已增加文件指纹检查。
- 转换流程拆分为核心转换成功和样式应用成功两个结果，避免部分成功被错误归类。
- 历史快照以文件和索引分离，重复保存受 30 秒节流和容量边界控制。
- 仍需人工确认关闭窗口、扩展重载和异常退出时的行为，因为 CustomReadonly 不是原生 TextDocument。

### 5.3 数据一致性

- 关键本地文件写入采用同目录临时文件加原子替换。
- 保存前检查当前磁盘文件哈希；保存后更新已知哈希。
- 原子写入防止截断，不提供断电持久性或跨进程锁。

### 5.4 性能和资源

- 历史快照和索引有数量、容量和时间边界。
- XLSX 稀疏范围校验避免不受控的内存和循环膨胀。
- 当前主要潜在成本是大 Markdown 每次渲染和 HTML 清理；个人工具规模内可接受，仍应使用大文档人工回归。
