# 代码审计报告：`2.0.1-local.1` 的 `main` 源码

审计时间：2026-09-28（北京时间）。审计对象：个人自用的 VS Code／Cursor／Antigravity 扩展 `muhammad-ahmad.xlsx-viewer`，`main` 提交 `41994f1127b5ddaa1cafc901405aaa4d0feefa09`。本报告只分析，不修复代码；报告本身未提交或推送。

## 一、一页式风险总览

**结论：当前版本不宜将 Markdown「预览编辑」的保存视为保真能力。** 已用项目锁定版本的 MarkdownIt／Turndown 组合复现：没有围栏代码或 Tab 的文档，`<mark>` 与 `==高亮==` 在渲染后回转为 Markdown 时变成普通文本。现有保护只拦截围栏与 Tab，因而没有覆盖这一输入。该缺陷为 P1，属于源文件内容损坏风险。其余发现为特定异常或长文档下的 P2 风险；未发现可据现有证据宣称的 P0 或远程代码执行。

| 等级 | 编号 | 结论 | 证据性质 |
| --- | --- | --- | --- |
| P1 | MD-01 | 预览编辑保存会删除高亮语义，并改写引用式链接 | 源码调用链＋依赖库独立复现；真实 IDE 保存待验 |
| P2 | HIST-01 | Markdown 保存成功后，30 秒内关闭面板会取消尚未落盘的历史快照 | 静态分析结论，触发链明确 |
| P2 | SAVE-01 | CSV／TSV 或 XLSX 主文件已写入后，辅助状态失败会返回“保存失败” | 静态分析结论，故障注入待验 |
| P2 | PERF-01 | 长 Markdown 文档每次输入仍触发整篇解析、DOM 替换及后处理 | 静态分析结论，性能阈值待实测 |

## 三、技术栈和模块概览

TypeScript 扩展由 `src/extension.ts` 注册自定义编辑器；`src/mdEditorProvider.ts` 与 `src/spreadsheetEditorProvider.ts` 承接 Webview 消息与本地写入；`src/webviews/md/mdWebview.ts` 使用 MarkdownIt、Turndown、Mermaid、KaTeX；表格链路使用 ExcelJS 与 CSV／TSV 转换。`src/shared/webviewMessageSchema.ts` 对消息和大小做校验，`src/shared/pathSafety.ts` 做路径包含检查，`src/shared/atomicFile.ts` 用同目录临时文件替换。无后端、数据库或多租户边界；主要资产是用户本地文件及 VS Code `workspaceState`。

| 置信度 | 高：静态调用顺序明确；实际故障注入待验 |
| 影响模块 | CSV／TSV 样式保存、XLSX 保存与版本历史 |
| 故障根因 | 主文件原子写成功后才写样式元数据或历史快照、刷新缓存；外层 `catch` 把后置步骤错误当作整个保存失败，没有区分“文件已落盘”。 |
| 代码证据 | CSV／TSV 在 `writeTabularFile()` 后调用 `saveMetadata()`；后者更新 `workspaceState`；XLSX 在 `writeFileAtomically()` 后调用 `persistVersionSnapshot()` 与 `loadWorkbookPayload()`；任一异常进入 `saveResult ok:false`。 |
| 文件路径 | `src/spreadsheetEditorProvider.ts`；`src/shared/styleStorageService.ts` |
| 代码行号 | `spreadsheetEditorProvider.ts:1020-1046, 1906-1930, 2392-2429`；`styleStorageService.ts:189-207` |
| 调用链 | `saveXlsxEdits`→写用户文件→更新样式／历史／缓存→后置步骤异常→统一失败回执。 |
| 触发条件 | 主文件写入已成功，但 `workspaceState.update()`、历史快照或工作簿刷新失败；具体发生率未测。 |
| 复现步骤 | 在临时 CSV／XLSX 副本中注入元数据更新或快照写入失败，记录保存回执、主文件哈希、样式状态；按 UI 提示重试含插入行／列的操作，检查是否重复。 |
| 复现结果 | 本次未故障注入；源码可确定存在主文件已写与失败回执共存的路径。 |
| 实际表现 | 回执可能写“失败”，而主文件内容已经改变；CSV 样式可能未保存。 |
| 预期表现 | 返回明确的“文件已保存、辅助状态失败”；需要重试时只重试未完成的辅助步骤，避免重复应用表格操作。 |
| 影响范围 | 仅后置辅助步骤异常的保存；正常路径不受影响。 |
| 安全影响 | 无已证实的远程安全影响。 |
| 业务影响 | 用户误判保存状态，重复点击可能造成重复结构操作。 |
| 数据影响 | 主文件与样式／历史状态可不一致；重试存在重复修改风险。 |
| 性能影响 | 故障重试增加 I/O；平时无直接影响。 |
| 利用难度 | 需触发本地异常；不是常规操作必现。 |
| 是否可远程利用 | 否。 |
| 是否需要登录权限 | 不适用。 |
| 修复建议 | 将“主文件写入”设为提交点；后续失败返回分阶段结果，禁止无条件重放原操作，并提供仅补存样式／快照的恢复路径。 |
| 短期止血方案 | 遇到保存失败先核对临时副本磁盘内容，勿盲目重复插入／删除操作。 |
| 长期治理方案 | 为保存结果建立明确状态：文件未写、文件已写但辅助步骤失败、全部成功；故障注入验证每一状态。 |

## 十一、上线阻断项
